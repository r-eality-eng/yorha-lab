> 论文口径：*FAST: Efficient Action Tokenization for Vision-Language-Action Models*  
> 作者：Physical Intelligence  
> 核心思想：用DCT（离散余弦变换）等信号压缩思想，把连续动作序列转换为更短的离散动作token序列；π0-FAST / FAST+ 可以理解为把 FAST tokenizer 接入 π0-style VLA 后形成的高效动作token版本。

> **优化补充：D117 学习导读**  
> D117 的核心不是“会写一个 DCT 函数”，而是理解动作 tokenization 的设计目标：用更少 token 表示更长、更平滑、更高保真的连续动作序列。传统 256 bins 是逐时间步、逐维度离散化；DCT/FAST-style 思路则先把动作序列变换到频域，再重点编码低频结构，从而提高 token 效率。

> **准确性与代码边界说明**  
> 下文 FAST tokenizer 代码是教学版，主要演示“时域动作 → 频域系数 → 离散 token → 反变换重建动作”的流程。真实 FAST / FAST+ 系统还包含更完整的动作序列离散化、quantization、BPE/序列压缩、词表集成和 tokenizer 训练流程。  
> 另外，DCT 代码要特别注意张量维度：动作通常是 `[B, T, D]`，DCT 应优先沿时间维 `T` 做变换；如果 einsum 写错，很容易把时间维和动作维混掉。后续生成 D117 HTML/代码版时，应把 DCT 实现改成可运行、可单测的版本。

> **FAST vs 256 bins 的合理比较口径**  
> - 256 bins 的优点是简单、解码快、容易接入 LM；缺点是 token 数随 `T * D` 线性增长，且逐维离散会损失时序结构。  
> - DCT/FAST-style 的优点是利用动作轨迹平滑性，用低频系数压缩时序；缺点是 tokenizer 更复杂，重建质量依赖频率截断、量化策略和数据分布。  
> - 速度比较不能只看 tokenization/detokenization，还要看 LM 生成 token 数、KV cache、词表大小、批量大小和硬件。

## 一、为什么需要动作Tokenization？

### 1.1 核心问题

```
传统动作生成方法的困境：

方法1: 连续回归（Flow Matching等）
  ✅ 高精度
  ❌ 推理慢（需要ODE求解）
  ❌ 难以利用语言模型的能力

方法2: 离散化（256bins等）
  ✅ 推理快（自回归生成）
  ❌ 精度损失大
  ❌ 需要大量bins才能保持精度

FAST / π0-FAST的目标：
  结合两者优势，实现：
  1. 高精度（连续动作的质量）
  2. 快推理（离散token的速度）
  3. 可扩展（与语言模型无缝集成）
```

### 1.2 FAST / π0-FAST的核心思想

```
传统离散化的问题：
  256bins对每个动作维度独立离散化 → 破坏动作序列的时序结构

FAST-style tokenizer的解决方案：
  先用DCT转换到频域，再对频域系数离散化 → 保持时序结构

DCT变换的直觉理解：
  原始动作序列: [a1, a2, a3, a4] (时域信号)
       ↓ DCT变换
  频域系数: [c0, c1, c2, c3] (低频→高频)
       ↓ 量化
  离散token: [t0, t1, t2, t3] (用少量token表示)
       ↓ 反量化 + IDCT
  重建动作: [â1, â2, â3, â4] (近似原始动作)

优势：
  1. DCT具有能量集中特性 → 低频系数包含主要信息
  2. 可以用少量token表示整个动作序列
  3. 保持动作的平滑性和时序结构
```

## 二、DCT变换基础

### 2.1 DCT数学原理

```python
"""
DCT-II变换公式（最常用）：

对于长度为N的序列x[n]，其DCT系数X[k]为：

X[k] = Σ_{n=0}^{N-1} x[n] * cos[π/N * (n + 0.5) * k], k=0,1,...,N-1

逆DCT（IDCT）公式：

x[n] = (1/N) * X[0] + (2/N) * Σ_{k=1}^{N-1} X[k] * cos[π/N * (n + 0.5) * k]

性质：
1. 正交变换：能量守恒
2. 能量集中：低频系数集中了大部分能量
3. 实数变换：输入输出都是实数
"""
```

### 2.2 PyTorch实现DCT

```python
import torch
import numpy as np

class DCTTransform:
    """
    教学版DCT变换工具类。

    约定:
      输入 actions 的形状是 [B, T, D]
      B = batch size
      T = action horizon / chunk length
      D = action dimension

    这个实现只沿时间维 T 做 DCT，不混合动作维 D。
    因此输出仍是 [B, T, D]，只是第二维从时域基变成频域基。
    """
    
    @staticmethod
    def _dct_matrix(n, device=None, dtype=None):
        """
        构造正交归一化 DCT-II 矩阵 C，形状 [T, T]。
        令 X = C @ x，IDCT 可用 x = C.T @ X 近似还原。
        """
        k = torch.arange(n, device=device, dtype=dtype).unsqueeze(1)      # [T, 1]
        t = torch.arange(n, device=device, dtype=dtype).unsqueeze(0)      # [1, T]
        C = torch.cos(np.pi / n * (t + 0.5) * k)                          # [T, T]
        C[0, :] *= np.sqrt(1.0 / n)
        C[1:, :] *= np.sqrt(2.0 / n)
        return C

    @staticmethod
    def dct_time(actions):
        """
        沿时间维做 DCT-II。
        
        Args:
            actions: [B, T, D] - 输入动作序列
        Returns:
            coeffs: [B, T, D] - 频域系数，T维表示频率index
        """
        assert actions.ndim == 3, "actions must be [B, T, D]"
        _, T, _ = actions.shape
        C = DCTTransform._dct_matrix(T, actions.device, actions.dtype)
        coeffs = torch.einsum("kt,btd->bkd", C, actions)
        return coeffs
    
    @staticmethod
    def idct_time(coeffs):
        """
        沿时间维做逆DCT。
        
        Args:
            coeffs: [B, T, D] - DCT系数
        Returns:
            actions: [B, T, D] - 重建动作序列
        """
        assert coeffs.ndim == 3, "coeffs must be [B, T, D]"
        _, T, _ = coeffs.shape
        C = DCTTransform._dct_matrix(T, coeffs.device, coeffs.dtype)
        actions = torch.einsum("kt,bkd->btd", C, coeffs)
        return actions


def test_dct_roundtrip():
    actions = torch.randn(2, 16, 7)
    coeffs = DCTTransform.dct_time(actions)
    recon = DCTTransform.idct_time(coeffs)
    max_err = (actions - recon).abs().max().item()
    print("max reconstruction error:", max_err)
    assert max_err < 1e-5
```

## 三、FAST Tokenizer实现

### 3.1 DCT Tokenizer核心类

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class FASTTokenizer(nn.Module):
    """
    FAST Tokenizer: 使用DCT进行动作tokenization
    
    步骤：
    1. DCT变换：时域 → 频域
    2. 频域量化：连续系数 → 离散token
    3. Token嵌入：离散token → 向量表示
    4. 反向：token → 系数 → 时域动作
    """
    
    def __init__(self, 
                 action_dim=7,
                 chunk_size=16,      # 动作序列长度
                 num_freq_bins=8,    # 保留的频率分量数
                 codebook_size=512,  # 码本大小
                 embedding_dim=256):
        super().__init__()
        
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        self.num_freq_bins = num_freq_bins  # 只保留低频分量
        self.codebook_size = codebook_size
        
        # DCT变换器
        self.dct = DCTTransform()
        
        # 频域选择：推理和训练时直接切片保留低频分量
        # 例如 dct_coeffs[:, :num_freq_bins, :]
        
        # 量化器：将连续系数映射到离散码本
        self.quantizer = VectorQuantizer(
            embedding_dim=action_dim,  # 每个频率分量独立量化
            num_embeddings=codebook_size,
            commitment_cost=0.25
        )
        
        # Token嵌入层（用于语言模型集成）
        self.token_embedding = nn.Embedding(codebook_size, embedding_dim)
        
    def tokenize(self, actions):
        """
        将连续动作序列转换为离散token序列
        
        Args:
            actions: [batch_size, chunk_size, action_dim] - 连续动作
        Returns:
            tokens: [batch_size, num_freq_bins] - 离散token
            quantized_coeffs: [batch_size, num_freq_bins, action_dim] - 量化后的频域系数
        """
        assert actions.ndim == 3, "actions must be [B, T, D]"
        assert actions.shape[1] == self.chunk_size
        assert actions.shape[2] == self.action_dim

        # 1. DCT变换：时域 → 频域
        dct_coeffs = self.dct.dct_time(actions)  # [batch, chunk_size, action_dim]
        
        # 2. 频率选择：只保留低频分量
        low_freq_coeffs = dct_coeffs[:, :self.num_freq_bins, :]
        
        # 3. 量化：连续系数 → 离散token
        # 这里采用“每个频率分量的D维向量对应一个token”的向量量化口径
        batch_size, num_freq_bins, action_dim = low_freq_coeffs.shape
        
        # 重塑为 [batch_size * num_freq_bins, action_dim]
        coeffs_flat = low_freq_coeffs.reshape(-1, action_dim)
        
        # 向量量化
        quantized_coeffs, tokens_flat, commitment_loss = self.quantizer(coeffs_flat)
        
        # tokens 是 [B, K]，不是 [B, K, D]
        # 如果希望得到 [B, K, D]，需要改用逐维标量量化器
        tokens = tokens_flat.reshape(batch_size, num_freq_bins)
        quantized_coeffs = quantized_coeffs.reshape(batch_size, num_freq_bins, action_dim)
        
        return tokens, quantized_coeffs, commitment_loss
    
    def detokenize(self, tokens):
        """
        将离散token转换回连续动作序列
        
        Args:
            tokens: [batch_size, num_freq_bins] - 离散token
        Returns:
            actions: [batch_size, chunk_size, action_dim] - 重建的连续动作
        """
        assert tokens.ndim == 2, "tokens must be [B, K] for vector-VQ FASTTokenizer"
        batch_size = tokens.shape[0]
        
        # 1. 反量化：token → 连续系数
        coeffs_flat = self.quantizer.embedding(tokens.reshape(-1))  # [batch*freq, action_dim]
        quantized_coeffs = coeffs_flat.reshape(batch_size, self.num_freq_bins, self.action_dim)
        
        # 2. 填充高频分量（用0填充）
        full_coeffs = torch.zeros(batch_size, self.chunk_size, self.action_dim, 
                                  device=tokens.device,
                                  dtype=quantized_coeffs.dtype)
        full_coeffs[:, :self.num_freq_bins, :] = quantized_coeffs
        
        # 3. 逆DCT变换：频域 → 时域
        actions = self.dct.idct_time(full_coeffs)
        
        return actions
    
    def forward(self, actions):
        """前向传播（用于训练）"""
        tokens, quantized_coeffs, commitment_loss = self.tokenize(actions)
        reconstructed_actions = self.detokenize(tokens)
        
        # 计算重建损失
        reconstruction_loss = F.mse_loss(reconstructed_actions, actions)
        
        return {
            'tokens': tokens,
            'reconstructed_actions': reconstructed_actions,
            'reconstruction_loss': reconstruction_loss,
            'commitment_loss': commitment_loss,
            'total_loss': reconstruction_loss + commitment_loss
        }

class VectorQuantizer(nn.Module):
    """
    向量量化器：用于将连续向量映射到离散码本
    """
    
    def __init__(self, num_embeddings, embedding_dim, commitment_cost=0.25):
        super().__init__()
        
        self.num_embeddings = num_embeddings
        self.embedding_dim = embedding_dim
        self.commitment_cost = commitment_cost
        
        # 码本（嵌入层）
        self.embedding = nn.Embedding(num_embeddings, embedding_dim)
        self.embedding.weight.data.uniform_(-1/num_embeddings, 1/num_embeddings)
    
    def forward(self, inputs):
        """
        Args:
            inputs: [batch_size, embedding_dim] - 输入向量
        Returns:
            quantized: [batch_size, embedding_dim] - 量化后的向量
            indices: [batch_size] - 码本索引（token）
            commitment_loss: 标量 - 承诺损失
        """
        # 计算输入向量与所有码本向量的距离
        distances = (torch.sum(inputs**2, dim=1, keepdim=True) 
                    + torch.sum(self.embedding.weight**2, dim=1)
                    - 2 * torch.matmul(inputs, self.embedding.weight.t()))
        
        # 找到最近的码本向量
        encoding_indices = torch.argmin(distances, dim=1)
        
        # 获取量化后的向量
        quantized = self.embedding(encoding_indices)
        
        # 计算承诺损失（鼓励输入靠近码本）
        commitment_loss = F.mse_loss(quantized.detach(), inputs)
        
        # 直通估计器：前向用量化值，反向用原始梯度
        quantized = inputs + (quantized - inputs).detach()
        
        return quantized, encoding_indices, self.commitment_cost * commitment_loss
```

### 3.2 FAST的层次化Tokenization

```python
class HierarchicalFASTTokenizer(nn.Module):
    """
    层次化FAST Tokenizer
    
    思想：不同频率分量使用不同的码本大小
    - 低频分量（重要信息）：大码本，高精度
    - 高频分量（细节信息）：小码本，低精度
    
    这样可以在保持精度的同时减少token数量
    """
    
    def __init__(self, 
                 action_dim=7,
                 chunk_size=16,
                 freq_bands=[0, 4, 8, 12],  # 频率分界点
                 codebook_sizes=[1024, 512, 256]):
        super().__init__()
        assert len(codebook_sizes) == len(freq_bands) - 1
        
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        self.freq_bands = freq_bands
        self.codebook_sizes = codebook_sizes
        
        # DCT变换
        self.dct = DCTTransform()
        
        # 为每个频段创建量化器
        self.quantizers = nn.ModuleList([
            VectorQuantizer(
                num_embeddings=codebook_size,
                embedding_dim=action_dim,
                commitment_cost=0.25
            )
            for codebook_size in codebook_sizes
        ])
        
        # Token嵌入（用于语言模型）
        total_tokens = sum(codebook_sizes)
        self.token_embedding = nn.Embedding(total_tokens, 256)
    
    def tokenize(self, actions):
        """
        层次化tokenization
        """
        # DCT变换
        dct_coeffs = self.dct.dct_time(actions)  # [batch, chunk_size, action_dim]
        
        all_tokens = []
        all_quantized = []
        total_commitment_loss = 0
        
        # 对每个频段独立量化
        for i, (low_freq, high_freq) in enumerate(zip(self.freq_bands[:-1], self.freq_bands[1:])):
            # 提取当前频段的系数
            band_coeffs = dct_coeffs[:, low_freq:high_freq, :]
            
            # 批量化处理
            batch_size, band_size, action_dim = band_coeffs.shape
            coeffs_flat = band_coeffs.reshape(-1, action_dim)
            
            # 量化
            quantized, tokens, commitment_loss = self.quantizers[i](coeffs_flat)
            
            # 重塑回原始形状
            tokens = tokens.reshape(batch_size, band_size)
            quantized = quantized.reshape(batch_size, band_size, action_dim)
            
            # 调整token索引（避免不同频段token冲突）
            token_offset = sum(self.codebook_sizes[:i])
            adjusted_tokens = tokens + token_offset
            
            all_tokens.append(adjusted_tokens)
            all_quantized.append(quantized)
            total_commitment_loss += commitment_loss
        
        # 合并所有频段
        tokens = torch.cat(all_tokens, dim=1)  # [batch, total_freq_bins]
        quantized_coeffs = torch.cat(all_quantized, dim=1)  # [batch, total_freq_bins, action_dim]
        
        return tokens, quantized_coeffs, total_commitment_loss
    
    def detokenize(self, tokens):
        """
        层次化反tokenization
        """
        batch_size = tokens.shape[0]
        
        all_coeffs = []
        cursor = 0
        
        # 逐频段处理
        for i, (low_freq, high_freq) in enumerate(zip(self.freq_bands[:-1], self.freq_bands[1:])):
            # 提取当前频段的token
            band_size = high_freq - low_freq
            # 注意：这里按“频段长度”切 token，不是按 codebook_size 切。
            # codebook_size 只表示 token 的取值范围，不表示 token 序列长度。
            band_tokens = tokens[:, cursor:cursor + band_size]
            cursor += band_size
            
            # 调整token索引（减去偏移）
            token_offset = sum(self.codebook_sizes[:i])
            band_tokens = band_tokens - token_offset
            
            # 反量化
            coeffs_flat = self.quantizers[i].embedding(band_tokens.reshape(-1))
            band_coeffs = coeffs_flat.reshape(batch_size, band_size, self.action_dim)
            
            all_coeffs.append(band_coeffs)
        
        # 合并并填充到完整长度
        quantized_coeffs = torch.cat(all_coeffs, dim=1)
        full_coeffs = torch.zeros(batch_size, self.chunk_size, self.action_dim, 
                                  device=tokens.device,
                                  dtype=quantized_coeffs.dtype)
        full_coeffs[:, :quantized_coeffs.shape[1], :] = quantized_coeffs
        
        # 逆DCT变换
        actions = self.dct.idct_time(full_coeffs)
        
        return actions
```

## 四、256bins离散化基线实现

```python
class BinsTokenizer(nn.Module):
    """
    传统256bins离散化方法
    
    方法：将每个动作维度独立均匀离散化为256个bins
    """
    
    def __init__(self, 
                 action_dim=7,
                 num_bins=256,
                 action_range=(-1.0, 1.0)):
        super().__init__()
        
        self.action_dim = action_dim
        self.num_bins = num_bins
        self.action_range = action_range
        
        # 计算每个bin的宽度
        self.bin_width = (action_range[1] - action_range[0]) / num_bins
        
        # Token嵌入（用于语言模型）
        # 每个动作维度独立的token空间
        self.token_embeddings = nn.ModuleList([
            nn.Embedding(num_bins, 64)
            for _ in range(action_dim)
        ])
        
        # 合并嵌入
        self.combine_embedding = nn.Linear(action_dim * 64, 256)
    
    def tokenize(self, actions):
        """
        将连续动作离散化为bin索引
        
        Args:
            actions: [batch_size, seq_len, action_dim] - 连续动作
        Returns:
            tokens: [batch_size, seq_len, action_dim] - bin索引（离散token）
        """
        # 归一化到[0, 1]
        actions_normalized = (actions - self.action_range[0]) / (self.action_range[1] - self.action_range[0])
        
        # 转换为bin索引
        tokens = (actions_normalized * (self.num_bins - 1)).long()
        
        # 裁剪到有效范围
        tokens = torch.clamp(tokens, 0, self.num_bins - 1)
        
        return tokens
    
    def detokenize(self, tokens):
        """
        将bin索引转换回连续动作
        
        Args:
            tokens: [batch_size, seq_len, action_dim] - bin索引
        Returns:
            actions: [batch_size, seq_len, action_dim] - 重建的连续动作
        """
        # 转换为连续值（每个bin的中心值）
        actions_normalized = tokens.float() / (self.num_bins - 1)
        
        # 反归一化
        actions = actions_normalized * (self.action_range[1] - self.action_range[0]) + self.action_range[0]
        
        return actions
    
    def forward(self, actions):
        """前向传播（用于训练）"""
        tokens = self.tokenize(actions)
        reconstructed_actions = self.detokenize(tokens)
        
        # 计算重建损失
        reconstruction_loss = F.mse_loss(reconstructed_actions, actions)
        
        return {
            'tokens': tokens,
            'reconstructed_actions': reconstructed_actions,
            'reconstruction_loss': reconstruction_loss,
            'commitment_loss': torch.tensor(0.0),  # 没有量化损失
            'total_loss': reconstruction_loss
        }

class MultiDimBinsTokenizer(nn.Module):
    """
    多维度联合离散化
    
    问题：独立离散化忽略动作维度之间的相关性
    解决方案：使用向量量化同时考虑所有维度
    """
    
    def __init__(self, 
                 action_dim=7,
                 num_bins_per_dim=16,  # 每个维度的bins数
                 embedding_dim=128):
        super().__init__()
        
        self.action_dim = action_dim
        self.num_bins_per_dim = num_bins_per_dim
        
        # 总的离散状态数 = (num_bins_per_dim)^action_dim
        # 对于7维动作，16^7 ≈ 268M，太大了！
        # 解决方案：使用层次化方法或哈希
        self.total_bins = num_bins_per_dim ** action_dim
        
        # 使用哈希映射减少内存占用
        self.hash_size = 65536  # 哈希表大小
        self.codebook = nn.Embedding(self.hash_size, embedding_dim)
        
        # 哈希函数
        self.hash_weights = nn.Parameter(
            torch.randn(action_dim, self.hash_size),
            requires_grad=False
        )
    
    def _hash_action(self, action_bins):
        """
        将多维bin索引哈希为单个索引
        """
        # action_bins: [batch, seq, action_dim]
        # 使用加权求和哈希
        weights = torch.arange(1, self.action_dim + 1).float()
        hash_value = (action_bins * weights).sum(dim=-1)
        hash_index = hash_value.long() % self.hash_size
        return hash_index
    
    def tokenize(self, actions):
        """将连续动作转换为哈希索引"""
        # 将每个维度离散化为bins
        bins_list = []
        for dim in range(self.action_dim):
            # 将动作值归一化到[0, 1]
            action_dim = actions[:, :, dim]
            action_normalized = (action_dim + 1) / 2  # 假设动作范围[-1, 1]
            
            # 转换为bin索引
            bin_index = (action_normalized * (self.num_bins_per_dim - 1)).long()
            bin_index = torch.clamp(bin_index, 0, self.num_bins_per_dim - 1)
            bins_list.append(bin_index)
        
        # 堆叠为多维bin索引
        multi_dim_bins = torch.stack(bins_list, dim=-1)  # [batch, seq, action_dim]
        
        # 哈希为单个索引
        hash_indices = self._hash_action(multi_dim_bins)
        
        return hash_indices
    
    def detokenize(self, hash_indices):
        """从哈希索引重建动作（近似）"""
        # 注意：哈希是不可逆的，所以这是近似重建
        # 实际应用中可能需要使用其他方法
        
        # 简单的近似：使用哈希索引获取码本向量
        embeddings = self.codebook(hash_indices)  # [batch, seq, embedding_dim]
        
        # 使用线性层将嵌入映射回动作空间
        # 这里简化处理，实际需要更复杂的映射
        actions_approx = torch.zeros(hash_indices.shape[0], hash_indices.shape[1], 
                                    self.action_dim, device=hash_indices.device)
        
        return actions_approx
```

### 6.1 FAST在VLA模型中的应用

```python
class PiZeroFAST(nn.Module):
    """
    使用FAST Tokenizer的π0变体
    
    架构变化：
    1. 使用FAST tokenizer将动作转换为离散token
    2. 与语言token一起输入VLM
    3. 自回归生成动作token
    4. 反tokenize回连续动作
    """
    
    def __init__(self, 
                 vlm_model,
                 action_dim=7,
                 chunk_size=16):
        super().__init__()
        
        # VLM骨干网络
        self.vlm = vlm_model
        
        # FAST Tokenizer
        self.fast_tokenizer = FASTTokenizer(
            action_dim=action_dim,
            chunk_size=chunk_size,
            num_freq_bins=8,
            codebook_size=512
        )
        
        # 语言模型头部（用于自回归生成token）
        self.lm_head = nn.Linear(self.vlm.config.hidden_size, 512)
        
        # 动作token嵌入
        self.action_token_embedding = nn.Embedding(512, self.vlm.config.hidden_size)
        
    def forward(self, images, language, target_actions=None):
        """
        前向传播
        
        Args:
            images: [B, C, H, W] - 图像输入
            language: [B, L] - 语言token
            target_actions: [B, chunk_size, action_dim] - 目标动作（训练时）
        """
        # 1. 将目标动作转换为token（训练时）
        if target_actions is not None:
            action_tokens, _, commitment_loss = self.fast_tokenizer.tokenize(target_actions)
            # action_tokens: [B, num_freq_bins, action_dim]
            
            # 重塑为序列形式
            batch_size = action_tokens.shape[0]
            action_tokens_flat = action_tokens.reshape(batch_size, -1)  # [B, num_freq_bins * action_dim]
        
        # 2. 准备输入序列
        # 语言token
        language_embeddings = self.vlm.get_input_embeddings()(language)
        
        # 图像token（假设VLM有图像编码器）
        image_tokens = self.vlm.encode_images(images)
        
        # 动作token（训练时）
        if target_actions is not None:
            action_embeddings = self.action_token_embedding(action_tokens_flat)
            input_embeddings = torch.cat([image_tokens, language_embeddings, action_embeddings], dim=1)
        else:
            input_embeddings = torch.cat([image_tokens, language_embeddings], dim=1)
        
        # 3. VLM前向传播
        vlm_output = self.vlm(inputs_embeds=input_embeddings)
        hidden_states = vlm_output.last_hidden_state
        
        # 4. 预测动作token
        # 提取动作部分的隐藏状态
        if target_actions is not None:
            action_hidden = hidden_states[:, -action_tokens_flat.shape[1]:, :]
        else:
            action_hidden = hidden_states[:, -8*7:, :]  # 预测8*7=56个token
        
        action_logits = self.lm_head(action_hidden)  # [B, seq_len, 512]
        
        if target_actions is not None:
            # 计算语言模型损失
            lm_loss = F.cross_entropy(
                action_logits.reshape(-1, 512),
                action_tokens_flat.reshape(-1)
            )
            
            # 总损失 = 语言模型损失 + 承诺损失
            total_loss = lm_loss + commitment_loss
            
            return {
                'logits': action_logits,
                'lm_loss': lm_loss,
                'commitment_loss': commitment_loss,
                'total_loss': total_loss,
                'action_tokens': action_tokens
            }
        else:
            # 推理时：自回归生成token
            return self._generate_action_tokens(action_logits)
    
    def _generate_action_tokens(self, action_logits):
        """自回归生成动作token"""
        # 贪心解码
        action_tokens = torch.argmax(action_logits, dim=-1)  # [B, seq_len]
        
        # 重塑为FAST token格式
        batch_size = action_tokens.shape[0]
        action_tokens_reshaped = action_tokens.reshape(batch_size, 8, 7)  # [B, num_freq_bins, action_dim]
        
        # 反tokenize
        reconstructed_actions = self.fast_tokenizer.detokenize(action_tokens_reshaped)
        
        return reconstructed_actions
    
    def generate_actions(self, images, language, max_new_tokens=56):
        """生成动作序列"""
        self.eval()
        with torch.no_grad():
            # 准备输入
            language_tokens = self.vlm.tokenizer.encode(language, return_tensors='pt')
            
            # 自回归生成
            generated_tokens = []
            
            for _ in range(max_new_tokens):
                # 前向传播
                outputs = self.forward(images, language_tokens)
                logits = outputs['logits']
                
                # 获取下一个token
                next_token = torch.argmax(logits[:, -1, :], dim=-1)
                generated_tokens.append(next_token)
                
                # 更新输入
                language_tokens = torch.cat([language_tokens, next_token.unsqueeze(1)], dim=1)
            
            # 重塑为FAST token
            action_tokens = torch.stack(generated_tokens, dim=1)
            action_tokens = action_tokens.reshape(-1, 8, 7)
            
            # 反tokenize
            actions = self.fast_tokenizer.detokenize(action_tokens)
            
            return actions
```

```python
class HybridTokenizer(nn.Module):
    """
    混合tokenization策略
    
    结合FAST和bins的优势：
    - 低频信息（主要运动模式）：使用FAST
    - 高频信息（细节调整）：使用bins
    """
    
    def __init__(self, action_dim=7, chunk_size=16):
        super().__init__()
        
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        
        # 分解为低频和高频部分
        self.low_freq_size = 4  # 低频分量数
        self.high_freq_size = chunk_size - self.low_freq_size
        
        # 低频：使用FAST
        self.fast_tokenizer = FASTTokenizer(
            action_dim=action_dim,
            chunk_size=self.low_freq_size,
            num_freq_bins=4,
            codebook_size=256
        )
        
        # 高频：使用bins（更少的bins，因为高频信息重要性较低）
        self.bins_tokenizer = BinsTokenizer(
            action_dim=action_dim,
            num_bins=64,
            action_range=(-0.5, 0.5)  # 高频部分幅度较小
        )
        
        # 分离网络：学习将动作分离为低频和高频
        self.separator = nn.Sequential(
            nn.Linear(chunk_size * action_dim, 256),
            nn.ReLU(),
            nn.Linear(256, chunk_size * action_dim * 2)
        )
    
    def tokenize(self, actions):
        """混合tokenization"""
        batch_size = actions.shape[0]
        
        # 1. 分离低频和高频成分
        actions_flat = actions.reshape(batch_size, -1)
        separated = self.separator(actions_flat)
        
        # 分割为低频和高频
        low_freq = separated[:, :self.low_freq_size * self.action_dim]
        high_freq = separated[:, self.low_freq_size * self.action_dim:]
        
        # 重塑
        low_freq = low_freq.reshape(batch_size, self.low_freq_size, self.action_dim)
        high_freq = high_freq.reshape(batch_size, self.high_freq_size, self.action_dim)
        
        # 2. 分别tokenize
        low_tokens, low_quantized, low_commit_loss = self.fast_tokenizer.tokenize(low_freq)
        high_tokens = self.bins_tokenizer.tokenize(high_freq)
        
        # 3. 合并token
        # 调整token索引避免冲突
        high_tokens_adjusted = high_tokens + 256  # 偏移bins的token
        
        # 合并
        all_tokens = torch.cat([low_tokens.reshape(batch_size, -1), 
                               high_tokens_adjusted.reshape(batch_size, -1)], dim=1)
        
        return all_tokens, (low_quantized, high_freq), low_commit_loss
    
    def detokenize(self, tokens):
        """混合反tokenization"""
        batch_size = tokens.shape[0]
        
        # 分离token
        low_tokens_flat = tokens[:, :self.low_freq_size * self.action_dim]
        high_tokens_flat = tokens[:, self.low_freq_size * self.action_dim:]
        
        # 调整高频token索引
        high_tokens_flat = high_tokens_flat - 256
        
        # 重塑
        low_tokens = low_tokens_flat.reshape(batch_size, self.low_freq_size, self.action_dim)
        high_tokens = high_tokens_flat.reshape(batch_size, self.high_freq_size, self.action_dim)
        
        # 反tokenize
        low_freq = self.fast_tokenizer.detokenize(low_tokens)
        high_freq = self.bins_tokenizer.detokenize(high_tokens)
        
        # 合并
        reconstructed = torch.cat([low_freq, high_freq], dim=1)
        
        return reconstructed
```

## 七、FAST Tokenizer训练流程：从离线动作数据到VLA词表

前面代码主要讲“怎么把动作变成 token”。但真实系统里，tokenizer 本身也需要训练、验证和接入。可以把完整流程拆成 6 个阶段：

```
原始机器人轨迹
  ↓
动作归一化 / 坐标系统一 / chunk切分
  ↓
DCT变换：时域动作 [T,D] → 频域系数 [T,D]
  ↓
低频选择：保留前K个频率，或按能量自适应选择
  ↓
量化器训练：VQ / k-means / residual quantization
  ↓
序列压缩：可选 BPE / unigram / run-length-style merge
  ↓
接入VLA：扩展词表或使用独立action head
```

### 7.1 数据预处理：不要直接对原始动作做DCT

不同机器人、不同数据集的动作定义可能完全不同：

- 有的动作是末端位姿增量：`Δx, Δy, Δz, Δroll, Δpitch, Δyaw, gripper`
- 有的动作是关节角目标：`q1...qn`
- 有的动作是速度或力控指令
- 有的夹爪动作范围是 `[0,1]`，有的是 `[-1,1]`，还有的是二值开合

因此 FAST tokenizer 训练前通常要先做统一预处理：

1. **坐标系统一**：世界坐标、相机坐标、机器人 base 坐标要明确。
2. **动作尺度归一化**：每一维最好有 `mean/std` 或 `min/max`，否则大尺度维度会主导码本。
3. **chunk切分**：把长轨迹切成固定长度 `T` 的 action chunk，例如 16、32、64。
4. **异常值裁剪**：极端动作会污染 DCT 系数和 VQ codebook。
5. **夹爪单独处理**：夹爪往往是离散或近似二值信号，不一定适合和连续位姿维度共用同一码本。

```python
class ActionNormalizer:
    """
    教学版动作归一化器。
    真实系统中 mean/std 应该由训练集统计得到，并随 tokenizer 一起保存。
    """

    def __init__(self, mean, std, eps=1e-6):
        self.mean = mean
        self.std = std
        self.eps = eps

    def encode(self, actions):
        return (actions - self.mean) / (self.std + self.eps)

    def decode(self, normalized_actions):
        return normalized_actions * (self.std + self.eps) + self.mean
```

### 7.2 量化器训练：核心不是“最近邻”，而是码本覆盖

VQ 的 forward 只是“把输入分配给最近码本向量”。训练阶段真正关键的是让码本覆盖动作频域系数的分布：

- 如果码本太小：重建误差大，动作会过度平滑。
- 如果码本太大：词表膨胀，稀有 token 多，VLA 更难学。
- 如果数据归一化差：码本会被某些大尺度维度占满。
- 如果低频 `K` 太小：动作趋势保留，但局部修正不足。
- 如果低频 `K` 太大：重建更好，但 token 数和生成成本上升。

常见训练目标可以写成：

```python
loss = reconstruction_loss + commitment_weight * commitment_loss
```

其中：

- `reconstruction_loss` 保证 detokenize 后动作接近原动作。
- `commitment_loss` 防止 encoder 输出在码本之间乱跳。
- 如果使用 residual quantization，还会逐级量化残差，让小码本组合表达更丰富的动作。

### 7.3 BPE / 序列压缩：FAST和语言模型之间的桥

动作 token 生成出来后，还可以继续做序列层面的压缩。直觉类似文本 BPE：

```
原始动作token序列：
  [12, 45, 45, 103, 88, 12, 45, 45, 103]

发现高频片段：
  [12, 45, 45, 103] 经常一起出现

合并成新token：
  [9001, 88, 9001]
```

这样做的收益是：

1. **更短的自回归序列**：VLA 解码步数更少。
2. **动作模式更语义化**：常见运动片段变成稳定 token。
3. **更适合长 horizon**：长动作 chunk 不一定线性增加 token 数。

但也有风险：

- BPE token 的可解释性更弱。
- 罕见动作可能被压缩得不好。
- 需要保证 detokenize 仍然能还原到有效动作序列。
- 词表扩展后，要处理文本 token 与动作 token 的 id 空间冲突。

### 7.4 接入VLA时的三种接口

| 接口方式 | 做法 | 优点 | 风险 |
|---|---|---|---|
| 扩展统一词表 | 把动作token加入LM vocabulary | 最接近文本生成范式 | 词表污染、训练不稳定 |
| 独立action head | VLA hidden state接一个动作token分类头 | 边界清晰，便于控制损失 | 与文本生成头分离，需要额外实现 |
| 混合接口 | 低频用动作token，高频由连续head修正 | 兼顾压缩和精度 | 系统更复杂，评估更难 |

实际做工程时，更推荐先用**独立 action head**把系统跑通，再考虑统一词表或 BPE 压缩。原因是独立 head 更容易排查问题：动作 token 预测错了，就是 action head、tokenizer 或数据对齐的问题；统一词表方案里，文本能力和动作能力会互相影响，debug 成本更高。

### 7.5 最小单测：防止tokenizer悄悄坏掉

FAST tokenizer 必须配套单测，否则很容易出现维度写错但训练还能跑的情况。


这些测试不能证明 tokenizer 一定好，但能防止最常见的低级错误：

- DCT 沿错维度。
- token shape 前后不一致。
- detokenize 后动作维度错。
- 高低频填充位置错。
- dtype / device 不一致。

### 8.1 量化与优化

```python
class OptimizedFASTTokenizer(nn.Module):
    """
    优化版FAST Tokenizer（用于实际部署）
    
    优化技术：
    1. 量化：INT8量化减少内存和计算
    2. 缓存：缓存DCT矩阵
    3. 并行化：GPU并行计算
    4. 选择性DCT：只对重要维度进行DCT
    """
    
    def __init__(self, action_dim=7, chunk_size=16):
        super().__init__()
        
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        
        # 预计算DCT矩阵并缓存
        self.register_buffer('dct_matrix', self._precompute_dct_matrix())

        # 选择性处理：只对重要动作维度进行DCT
        self.important_dims = [0, 1, 2, 6]  # 位置和夹爪
        self.num_important = len(self.important_dims)
        
        # 量化器（INT8）
        self.quantizer = QuantizedVectorQuantizer(
            num_embeddings=256,
            embedding_dim=self.num_important,
            quantize=True
        )
        
    def _precompute_dct_matrix(self):
        """预计算DCT矩阵"""
        n = self.chunk_size
        k = torch.arange(n).float().unsqueeze(1)
        n_idx = torch.arange(n).float().unsqueeze(0)
        
        dct_matrix = torch.cos(np.pi * (n_idx + 0.5) * k / n)
        
        # 归一化
        dct_matrix[0, :] /= np.sqrt(n)
        dct_matrix[1:, :] /= np.sqrt(n / 2)
        
        return dct_matrix
    
    def tokenize_fast(self, actions):
        """优化tokenization"""
        batch_size = actions.shape[0]
        
        # 只处理重要维度
        important_actions = actions[:, :, self.important_dims]  # [B, chunk_size, num_important]
        
        # DCT变换（使用预计算的矩阵）
        dct_coeffs = torch.einsum('kt,btd->bkd', self.dct_matrix, important_actions)
        
        # 只保留低频分量
        low_freq_coeffs = dct_coeffs[:, :8, :]  # 只保留前8个频率
        
        # 量化
        quantized, tokens, commit_loss = self.quantizer(
            low_freq_coeffs.reshape(-1, self.num_important)
        )
        
        # 重塑
        tokens = tokens.reshape(batch_size, 8)
        
        return tokens, quantized, commit_loss
    
    def detokenize_fast(self, tokens):
        """优化反tokenization"""
        batch_size = tokens.shape[0]
        
        # 反量化
        coeffs = self.quantizer.embedding(tokens.reshape(-1))
        coeffs = coeffs.reshape(batch_size, 8, self.num_important)
        
        # 填充到完整长度
        full_coeffs = torch.zeros(batch_size, self.chunk_size, self.num_important,
                                 device=tokens.device,
                                 dtype=coeffs.dtype)
        full_coeffs[:, :8, :] = coeffs
        
        # IDCT变换
        reconstructed_important = torch.einsum('kt,bkd->btd', self.dct_matrix, full_coeffs)
        
        # 重建完整动作
        reconstructed = torch.zeros(batch_size, self.chunk_size, self.action_dim,
                                    device=tokens.device,
                                    dtype=coeffs.dtype)
        reconstructed[:, :, self.important_dims] = reconstructed_important
        
        return reconstructed

class QuantizedVectorQuantizer(nn.Module):
    """INT8量化版向量量化器"""
    
    def __init__(self, num_embeddings, embedding_dim, quantize=True):
        super().__init__()
        
        self.num_embeddings = num_embeddings
        self.embedding_dim = embedding_dim
        self.quantize = quantize
        
        # 码本（可能量化）
        self.embedding = nn.Embedding(num_embeddings, embedding_dim)
        
        if quantize:
            # 教学版使用固定量化参数。
            # 真实部署中通常要通过校准集统计 activation range。
            self.register_buffer("scale", torch.tensor(0.02))
            self.register_buffer("zero_point", torch.tensor(0, dtype=torch.int))
    
    def forward(self, inputs):
        if self.quantize:
            # 量化输入
            inputs_quantized = torch.quantize_per_tensor(
                inputs,
                scale=float(self.scale.item()),
                zero_point=int(self.zero_point.item()),
                dtype=torch.qint8
            )
            inputs_dequantized = inputs_quantized.dequantize()
        else:
            inputs_dequantized = inputs
        
        # 正常的向量量化
        distances = (torch.sum(inputs_dequantized**2, dim=1, keepdim=True) 
                    + torch.sum(self.embedding.weight**2, dim=1)
                    - 2 * torch.matmul(inputs_dequantized, self.embedding.weight.t()))
        
        encoding_indices = torch.argmin(distances, dim=1)
        quantized = self.embedding(encoding_indices)
        
        commitment_loss = F.mse_loss(quantized.detach(), inputs_dequantized)
        quantized = inputs_dequantized + (quantized - inputs_dequantized).detach()
        
        return quantized, encoding_indices, commitment_loss
```

### 8.2 关键实现坑位与修正版接口

上面的代码能帮助理解 FAST-style tokenizer 的模块边界，但如果直接拿去跑，会遇到几个典型问题。这里把最重要的工程修正单独列出来，避免把“教学草图”误当成“可运行实现”。

**坑位1：FAST token 的形状要先说清楚**

如果使用 `VectorQuantizer(embedding_dim=action_dim)`，含义是：每一个低频 DCT 系数向量 `[D]` 映射成一个码本索引。因此：

- 低频系数形状：`[B, K, D]`
- flatten 后送入 VQ：`[B*K, D]`
- token 形状应为：`[B, K]`
- 反量化后的系数形状：`[B, K, D]`

也就是说，这种写法不是“每个动作维度一个 token”，而是“每个频率分量一个 token”。如果想做“每个频率、每个动作维度一个 token”，那就应该改成标量量化器，输入是 `[B*K*D, 1]`，token 才会是 `[B,K,D]`。

```python
class FASTTokenizerVQ(nn.Module):
    """
    可运行口径的 FAST-style VQ tokenizer。

    约定:
      actions: [B, T, D]
      K = num_freq_bins
      每个低频向量 [D] 量化成 1 个 token

    输出:
      tokens: [B, K]
      reconstructed_actions: [B, T, D]
    """

    def __init__(self, action_dim=7, chunk_size=16, num_freq_bins=8, codebook_size=512):
        super().__init__()
        assert num_freq_bins <= chunk_size
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        self.num_freq_bins = num_freq_bins
        self.quantizer = VectorQuantizer(
            num_embeddings=codebook_size,
            embedding_dim=action_dim,
            commitment_cost=0.25,
        )

    def tokenize(self, actions):
        assert actions.ndim == 3
        assert actions.shape[1] == self.chunk_size
        assert actions.shape[2] == self.action_dim

        coeffs = DCTTransform.dct_time(actions)                 # [B, T, D]
        low = coeffs[:, :self.num_freq_bins, :]                 # [B, K, D]
        B, K, D = low.shape
        quantized, token_flat, commit_loss = self.quantizer(low.reshape(B * K, D))
        tokens = token_flat.reshape(B, K)                       # [B, K]
        quantized = quantized.reshape(B, K, D)                  # [B, K, D]
        return tokens, quantized, commit_loss

    def detokenize(self, tokens):
        assert tokens.ndim == 2
        B, K = tokens.shape
        assert K == self.num_freq_bins

        quantized = self.quantizer.embedding(tokens.reshape(-1))
        quantized = quantized.reshape(B, K, self.action_dim)

        full = torch.zeros(
            B,
            self.chunk_size,
            self.action_dim,
            device=tokens.device,
            dtype=quantized.dtype,
        )
        full[:, :K, :] = quantized
        return DCTTransform.idct_time(full)

    def forward(self, actions):
        tokens, quantized, commit_loss = self.tokenize(actions)
        recon = self.detokenize(tokens)
        recon_loss = F.mse_loss(recon, actions)
        return {
            "tokens": tokens,
            "quantized_coeffs": quantized,
            "reconstructed_actions": recon,
            "reconstruction_loss": recon_loss,
            "commitment_loss": commit_loss,
            "total_loss": recon_loss + commit_loss,
        }
```

**坑位2：层次化 token 的切片依据是频段长度，不是码本大小**

层次化 tokenizer 中，每个频段产生多少 token，取决于 `high_freq - low_freq`，而不是这个频段的 `codebook_size`。`codebook_size` 只决定每个 token 的取值范围。正确切片应维护一个 `cursor`：

```python
def split_hierarchical_tokens(tokens, freq_bands):
    """
    tokens: [B, total_kept_freq]
    freq_bands: 例如 [0, 4, 8, 12]
    """
    pieces = []
    cursor = 0
    for low, high in zip(freq_bands[:-1], freq_bands[1:]):
        band_size = high - low
        pieces.append(tokens[:, cursor:cursor + band_size])
        cursor += band_size
    return pieces
```

**坑位3：部署版 detokenize 不能引用未定义的 actions**

如果只重建部分重要维度，就必须明确输出动作的完整形状。可以先用 0 填充，再把重要维度写回去：

```python
def detokenize_fast(self, tokens):
    batch_size = tokens.shape[0]
    coeffs = self.quantizer.embedding(tokens.reshape(-1))
    coeffs = coeffs.reshape(batch_size, 8, self.num_important)

    full_coeffs = torch.zeros(
        batch_size,
        self.chunk_size,
        self.num_important,
        device=tokens.device,
        dtype=coeffs.dtype,
    )
    full_coeffs[:, :8, :] = coeffs

    reconstructed_important = torch.einsum(
        "kt,bkd->btd",
        self.dct_matrix,
        full_coeffs,
    )

    reconstructed = torch.zeros(
        batch_size,
        self.chunk_size,
        self.action_dim,
        device=tokens.device,
        dtype=coeffs.dtype,
    )
    reconstructed[:, :, self.important_dims] = reconstructed_important
    return reconstructed
```

**坑位4：FAST 与语言模型集成时，动作 token 需要独立位置编码**

动作 token 的位置不是普通文本位置。更合理的做法是至少区分三类位置：

1. 文本 token 位置：表示语言序列顺序。
2. 图像 token 位置：表示 patch 或视觉 token 顺序。
3. 动作 token 位置：表示频率 index、动作 chunk index，必要时还要区分机器人 embodiment。

如果不区分这些位置，模型可能只学到“动作 token 是一串离散 id”，但不理解第 0 个 token 是低频全局趋势、第 7 个 token 是更细的局部修正。

**坑位5：不要只比较 tokenizer 的局部速度**

FAST 的收益通常不来自“DCT 本身比 bins 更便宜”，而来自整体生成链路：

- 自回归步数更少：`K` 通常小于 `T*D` 或低于逐维逐步 token 序列。
- KV cache 压力更小：生成 token 少，Transformer 解码长度短。
- 动作更平滑：低频结构天然适合机器人轨迹。
- 误差形态更可控：丢掉高频往往表现为动作变平滑，而不是逐维抖动。

因此，严谨对比应该同时报告：

| 维度 | 应该报告什么 |
|---|---|
| 重建质量 | MSE、MAE、最大误差、轨迹平滑性、终点误差 |
| 控制表现 | 成功率、平均完成时间、碰撞率、重规划次数 |
| 生成成本 | 动作 token 数、解码步数、KV cache、端到端延迟 |
| 鲁棒性 | 不同机器人、不同动作尺度、不同任务分布下的泛化 |
| 工程成本 | tokenizer 训练、码本维护、词表扩展、线上回滚难度 |

## 九、总结与对比

### 9.1 核心对比结果

```
FAST vs 256bins 综合对比：

1. 速度：
   - Tokenization: FAST稍慢（需要DCT变换），但可优化
   - Detokenization: FAST明显快（只需查表+IDCT）
   - 总体推理速度：FAST更快（token数量少，自回归步骤少）

2. 精度：
   - MSE: FAST更低（DCT的能量集中特性）
   - 平滑性：FAST更好（保持时序结构）
   - 最大误差：FAST更小（避免极端量化误差）

3. Token效率：
   - FAST: 56 tokens/样本（8频率 × 7维度）
   - 256bins: 112 tokens/样本（16步 × 7维度）
   - 效率比：FAST ≈ 2× 更高效

4. 内存占用：
   - FAST: 码本大小 512 × 7 = 3.5KB
   - 256bins: 需要 256^7 ≈ 268MB（不可行）或 256×7 = 1.7KB（但精度损失大）

5. 适用场景：
   - FAST: 长动作序列，需要高保真度，与语言模型集成
   - 256bins: 短动作序列，实时性要求极高，资源受限
```

### 9.2 面试要点

**Q1: 为什么FAST使用DCT变换？**
A1: 三个主要原因：
1. **能量集中**：DCT将信号能量集中在低频分量，可以用少量系数表示主要信息
2. **去相关**：DCT系数之间相关性低，适合独立量化
3. **平滑性**：DCT基函数是平滑的，重建的动作序列也平滑

**Q2: FAST如何与语言模型集成？**
A2: 主要集成方式：
1. **统一词表**：将动作token与语言token放在同一词表中
2. **自回归生成**：像生成语言一样生成动作token序列
3. **混合输入**：图像token、语言token、动作token一起输入Transformer

**Q3: 实际部署时有哪些优化技巧？**
A3: 关键优化：
1. **预计算DCT矩阵**：避免重复计算
2. **选择性DCT**：只对重要维度/频率进行变换
3. **量化**：INT8量化减少内存和计算
4. **缓存**：缓存常用的token序列
5. **并行化**：GPU并行计算DCT和量化

**Q4: FAST在长horizon任务中的优势是什么？**
A4: 主要优势：
1. **压缩率高**：长序列可以压缩为少量token
2. **保持时序结构**：DCT保持时间相关性
3. **与推理层兼容**：离散token便于与VLM推理层集成
4. **渐进生成**：可以逐步生成token，实现流式输出

### 9.3 未来方向

1. **自适应DCT**：根据动作特性自动选择频率分量数
2. **混合精度**：不同频率使用不同精度的码本
3. **端到端学习**：学习最优的DCT基函数
4. **跨模态对齐**：对齐动作token和语言token的语义空间

π-FAST通过巧妙的DCT变换，实现了高效且高保真的动作tokenization，是连接连续动作控制与离散语言模型的重要桥梁。
