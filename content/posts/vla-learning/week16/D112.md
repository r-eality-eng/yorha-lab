### 1.0.2 复现失败排查表

| 现象 | 优先检查 | 常见原因 | 修复建议 |
|---|---|---|---|
| 模型加载失败 | checkpoint、`trust_remote_code`、transformers版本 | 权重不完整、版本不匹配 | 固定 revision，记录依赖版本 |
| processor 加载失败 | processor config、tokenizer 文件 | 本地目录缺文件 | 重新下载并校验文件列表 |
| 动作维度不对 | ActionTokenizer、`predict_action` 输出 | 手写解码或 API 不一致 | 使用官方 `predict_action` 或 ActionTokenizer |
| 动作范围异常 | `unnorm_key`、action stats | 训练/推理数据集统计不一致 | 核对 dataset stats 和动作空间 |
| 延迟异常高 | dtype、device、量化是否生效 | 模型在 CPU、KV cache/量化未启用 | 打印 device map，分段 profiling |
| 成功率低 | prompt、数据 split、环境随机性 | 评估协议不一致或任务分布偏移 | 固定 seed，保存失败视频和动作轨迹 |
| 报告数字复现不了 | config hash、checkpoint、seed | 实验上下文缺失 | 强制输出 `experiment_context` |

### 1.1.1 脚本安全执行口径

上面的环境搭建代码为了讲解流程，使用了若干 `subprocess.run(..., shell=True)`。真实复现项目里，建议更保守：

1. 优先使用参数列表形式，例如 `subprocess.run(["conda", "env", "create", "-f", env_file])`。
2. 不要把用户输入直接拼进 shell 命令。
3. 每条外部命令都记录 `stdout`、`stderr`、返回码和耗时。
4. 失败时输出可操作错误，而不是只打印异常。
5. 下载模型、数据和依赖时记录 URL、revision、hash 或版本号。

安全执行示例：

```python
def run_command(args, cwd=None, timeout=None):
    """
    更适合复现工程的命令执行封装。
    避免shell=True，保留stdout/stderr，便于报告和debug。
    """
    import subprocess
    import time

    start = time.time()
    result = subprocess.run(
        args,
        cwd=cwd,
        timeout=timeout,
        text=True,
        capture_output=True,
        check=False,
    )
    duration = time.time() - start

    record = {
        "cmd": args,
        "cwd": str(cwd) if cwd else None,
        "returncode": result.returncode,
        "stdout": result.stdout[-4000:],
        "stderr": result.stderr[-4000:],
        "duration_sec": duration,
    }

    if result.returncode != 0:
        raise RuntimeError(f"命令执行失败: {args}\n{result.stderr[-1000:]}")

    return record
```

    def _test_basic_inference(self, test_case: Dict) -> Dict:
        """测试基本推理功能"""
        result = {"passed": True, "error": None, "metrics": {}, "details": {}}
        
        try:
            # 准备输入
            image = test_case["image"]
            instruction = test_case["instruction"]
            
            # 构造提示
            prompt = f"In: What action should the robot take to {instruction}?\nOut:"
            
            # 处理输入
            inputs = self.processor(prompt, image).to(self.device)
            
            # 推理
            start_time = time.time()
            with torch.no_grad():
                outputs = self.model.generate(
                    **inputs,
                    max_new_tokens=7,
                    do_sample=False,
                )
            inference_time = time.time() - start_time
            
            # 解码动作：复现验证中不要手写token offset。
            # 正式代码优先使用 model.predict_action(...)；
            # 如需分析generate输出，应调用当前OpenVLA版本的官方ActionTokenizer。
            action_tokens = outputs[0, -7:].cpu()
            actions = self.action_tokenizer.decode_token_ids_to_actions(action_tokens)
            actions = np.array(actions)
            
            # 验证结果
            expected_range = test_case["expected_action_range"]
            expected_dims = test_case["expected_dims"]
            
            # 检查动作维度
            if len(actions) != expected_dims:
                result["passed"] = False
                result["error"] = f"动作维度错误: 期望{expected_dims}，实际{len(actions)}"
                return result
            
            # 检查动作范围
            if np.any(actions < expected_range[0]) or np.any(actions > expected_range[1]):
                result["passed"] = False
                result["error"] = f"动作超出范围: {actions}"
                return result
            
            # 记录指标
            result["metrics"] = {
                "inference_time_ms": inference_time * 1000,
                "action_mean": np.mean(actions),
                "action_std": np.std(actions),
                "action_min": np.min(actions),
                "action_max": np.max(actions),
            }
            
            result["details"] = {
                "actions": actions.tolist(),
                "action_tokens": action_tokens,
                "prompt": prompt,
            }
            
        except Exception as e:
            result["passed"] = False
            result["error"] = str(e)
        
        return result
    
    def _test_performance(self, test_case: Dict) -> Dict:

        try:
            # 准备数据
            image = test_case["image"]
            instruction = test_case["instruction"]
            prompt = f"In: What action should the robot take to {instruction}?\nOut:"

                inputs = self.processor(prompt, image).to(self.device)
                with torch.no_grad():
                    _ = self.model.generate(**inputs, max_new_tokens=7, do_sample=False)

                inputs = self.processor(prompt, image).to(self.device)

                latencies.append(latency)
            
            avg_latency = np.mean(latencies)
            std_latency = np.std(latencies)
            
            # 测量显存
            memory_allocated = torch.cuda.memory_allocated() / 1e9
            memory_reserved = torch.cuda.memory_reserved() / 1e9
            
            # 记录指标
            result["metrics"] = {
                "avg_latency_ms": avg_latency,
                "std_latency_ms": std_latency,
                "min_latency_ms": np.min(latencies),
                "max_latency_ms": np.max(latencies),
                "memory_allocated_gb": memory_allocated,
                "memory_reserved_gb": memory_reserved,
                "throughput_fps": 1000 / avg_latency if avg_latency > 0 else 0,
            }
            
            # 检查是否满足期望
            expected_latency = test_case.get("expected_latency_ms", 200)
            expected_memory = test_case.get("expected_memory_gb", 15.0)
            
            if avg_latency > expected_latency * 1.2:  # 允许20%波动
                result["passed"] = False
                result["error"] = f"延迟过高: {avg_latency:.1f}ms (期望<{expected_latency}ms)"
            
            if memory_allocated > expected_memory * 1.1:  # 允许10%波动
                result["passed"] = False
                result["error"] = f"显存过高: {memory_allocated:.1f}GB (期望<{expected_memory}GB)"
            
        except Exception as e:
            result["passed"] = False
            result["error"] = str(e)
        
        return result
    
    def _test_batch_processing(self, test_case: Dict) -> Dict:
        """测试批处理"""
        result = {"passed": True, "error": None, "metrics": {}, "details": {}}
        
        try:
            images = test_case["images"]
            instructions = test_case["instructions"]
            batch_size = test_case["batch_size"]
            
            # 准备批处理输入
            prompts = [
                f"In: What action should the robot take to {inst}?\nOut:"
                for inst in instructions
            ]
            
            # 单条处理时间
            single_times = []
            for i in range(batch_size):
                inputs = self.processor(prompts[i], images[i]).to(self.device)
                
                torch.cuda.synchronize()
                start_time = time.time()
                
                with torch.no_grad():
                    _ = self.model.generate(**inputs, max_new_tokens=7, do_sample=False)
                
                torch.cuda.synchronize()
                single_times.append(time.time() - start_time)
            
            avg_single_time = np.mean(single_times)
            
            # 批处理时间
            torch.cuda.synchronize()
            batch_start = time.time()
            
            # 这里简化处理，实际需要实现真正的批处理
            # OpenVLA的processor可能不支持真正的批处理
            for i in range(batch_size):
                inputs = self.processor(prompts[i], images[i]).to(self.device)
                with torch.no_grad():
                    _ = self.model.generate(**inputs, max_new_tokens=7, do_sample=False)
            
            torch.cuda.synchronize()
            batch_time = time.time() - batch_start
            
            # 计算加速比
            speedup = (avg_single_time * batch_size) / batch_time
            
            # 记录指标
            result["metrics"] = {
                "avg_single_time_ms": avg_single_time * 1000,
                "batch_time_ms": batch_time * 1000,
                "speedup": speedup,
                "expected_speedup": test_case.get("expected_speedup", 2.0),
            }
            
            # 检查加速比
            expected_speedup = test_case.get("expected_speedup", 2.0)
            if speedup < expected_speedup * 0.8:  # 允许20%波动
                result["passed"] = False
                result["error"] = f"加速比不足: {speedup:.2f}x (期望>{expected_speedup}x)"
            
        except Exception as e:
            result["passed"] = False
            result["error"] = str(e)
        
        return result
    
    def generate_validation_report(self, output_path: str = "validation_report.json"):
        """生成验证报告"""
        # 运行验证
        results = self.run_validation()
        
        # 添加系统信息
        report = {
            "timestamp": time.strftime("%Y-%m-%d %H:%M:%S"),
            "system_info": {
                "device": self.device,
                "model_path": str(self.model_path),
                "torch_version": torch.__version__,
                "cuda_version": torch.version.cuda if torch.cuda.is_available() else "N/A",
                "gpu_name": torch.cuda.get_device_name(0) if torch.cuda.is_available() else "N/A",
            },
            "validation_results": results,
        }
        
        # 保存报告
        with open(output_path, 'w') as f:
            json.dump(report, f, indent=2, default=str)
        
        print(f"\\n验证报告已保存: {output_path}")
        
        return report

## 二、深度分析报告撰写

### 2.0 报告数字上下文模板

技术报告最常见的问题不是“没有数字”，而是“数字没有上下文”。D112 的报告必须让读者知道：这个结果在什么模型、什么数据、什么硬件、什么评估协议下得到。

```yaml
experiment_context:
  model: openvla/openvla-7b
  checkpoint: hf_revision_or_local_hash
  dataset: bridge_orig_or_custom_dataset
  split: held_out_episodes
  num_episodes: 100
  seeds: [0, 1, 2]
  hardware: A100-80G
  dtype: bf16
  quantization: none
  prompt_template: "In: What action should the robot take to {instruction}? Out:"
  action:
    tokenizer: official_openvla_action_tokenizer
    unnorm_key: bridge_orig
    dims: 7
metrics:
  success_rate: 0.0
  action_mae_xyz: 0.0
  action_mae_rot: 0.0
  gripper_error: 0.0
  latency_ms:
    mean: 0.0
    p50: 0.0
    p90: 0.0
    p99: 0.0
  memory_gb:
    peak: 0.0
```

**写作原则**：

1. 任何“提升 X%”“节省 YGB”“成功率 Z%”都必须能追溯到实验配置。
2. 报告里不要只写平均延迟，要写 p50/p90/p99。
3. 量化和微调结果必须和 BF16/原始模型基线放在同一张表里。
4. 失败分析要保存视频、动作轨迹、prompt、环境状态和配置。
5. 面试时可以讲示例数字，但必须主动说明“这是某个配置下的实验结果，不是模型永恒属性”。

**5分钟版本：适合项目深挖**

5. **优化**：量化用于降低显存和延迟，但必须验证动作质量；LoRA 用于新任务适配，但要防止 loss 下降而成功率不升。
