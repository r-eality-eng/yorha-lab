RT-1：把视觉、语言和动作接成一个机器人策略

这一天的核心不是背模型名，而是理解 VLA 的第一条完整工程路径： 语言通过 FiLM 调制视觉特征，TokenLearner 压缩关键视觉信息，Transformer 根据历史上下文预测离散化动作，最终还原为机器人控制命令。

学习目标：D99 要真正解决的三个问题

RT-1 是理解 VLA 的第一块基石。它不像后来的 RT-2/OpenVLA 那样直接站在大规模 VLM 上， 但它清晰定义了“视觉 + 语言 → 动作”的机器人学习范式。

问题 1

架构如何闭环？

理解图像、语言、历史动作和机器人状态如何进入模型，并最终输出 7 维动作。

问题 2

为什么这样设计？

FiLM、TokenLearner、Transformer、256 bins 分别解决语言融合、视觉压缩、时序建模和动作表示问题。

问题 3

数据为什么关键？

RT-1 的泛化能力来自模型设计，也来自大规模、多样化、真实机器人演示数据。

一句话抓主线： RT-1 不是“给图片配一句话再回归动作”这么简单，而是让语言深入调制视觉特征，再用压缩后的视觉 token 和历史上下文预测离散动作。

RT-1 在 VLA 技术演进中的位置

RT-1 的意义在于证明：只要有足够多样的真实机器人数据，Transformer 可以学习多任务语言条件操作策略。 它没有 RT-2 那种强大的互联网语义迁移能力，但它把 VLA 的基本工程接口讲清楚了。

RT-1 整体架构：从观测到动作的闭环

RT-1 的输入不是单一图像，而是包含视觉观测、自然语言指令、历史动作和机器人状态的控制上下文。 它的输出也不是一句文本，而是可执行的机器人动作。

教学抽象说明： 本页为了帮助理解，把 RT-1 抽象为“视觉 + 语言 + 历史上下文 → 7维动作 × 256 bins”的主线。 真实论文和实现中的动作空间、token 数量、历史窗口、FiLM 插入位置和训练细节可能因版本与实验设置不同而变化； 面试或复现时应以论文和官方代码为最终依据。

输入

  • 图像：机器人视角或外部相机 RGB 图像。
  • 语言：自然语言任务指令，例如“把红色杯子拿起来”。
  • 历史上下文：之前的动作、本体状态、当前控制阶段。

输出

典型动作可理解为 7 维：三维平移、三维旋转和夹爪开合。RT-1 的关键处理方式是把每个连续维度离散化为分类问题，而不是直接用 MSE 回归。

FiLM EfficientNet：语言如何进入视觉特征

FiLM 的全称是 Feature-wise Linear Modulation。它的核心思想是： 用语言指令生成一组通道级参数，让视觉网络在提取特征时就“知道当前任务是什么”。

数学形式： 对视觉特征图 F ∈ R^(C×H×W)，语言嵌入生成 γ ∈ R^C 和 β ∈ R^C， 然后执行 F'_{c,h,w} = γ_c · F_{c,h,w} + β_c。

直觉解释

如果指令是“拿起红色杯子”，语言编码器会把“红色”“杯子”“拿起”这些语义压缩成向量。 FiLM 再根据这个向量生成调制参数，让 EfficientNet 中与红色、杯子、可抓取区域相关的通道更强， 与背景或无关物体相关的通道更弱。

所以 FiLM 更像给视觉系统戴上了一副“任务滤镜”：不是看见所有东西都同等重要，而是按照语言指令重新分配视觉特征的重要性。

FiLM 与其他融合方式的对比

FiLM：轻量、早期、通道级调制

语言生成 γ, β，直接调制视觉特征通道。优点是计算轻、适合实时控制，缺点是表达能力比 cross-attention 弱。

拼接：简单但偏浅层

把视觉特征和语言向量拼起来再送入 MLP 或 Transformer。实现简单，但语言往往只能在后面影响决策，不能深度改变视觉特征提取过程。

Cross-Attention：强表达但更重

视觉 token 查询语言 token，或语言 token 查询视觉 token。表达能力强、可解释性好，但计算量更高，早期机器人实时控制场景不一定划算。

TokenLearner：把大视觉特征压缩成少量关键 token

视觉 backbone 输出的特征图包含很多空间位置。如果直接把所有位置都送给 Transformer，序列变长，注意力计算变慢。 TokenLearner 的目标是学习出少量信息密度更高的 token。

解决的问题

假设 EfficientNet 输出 H×W 个空间 token。每个 token 都进入 Transformer 时， self-attention 复杂度随序列长度近似二次增长。对于机器人控制来说，推理速度直接影响控制频率。

核心思想

学习若干个空间注意力图，每个注意力图负责从原始特征图中汇聚一种任务相关信息，例如目标物体、夹爪位置、放置区域或背景参考。

为什么 TokenLearner 对机器人控制重要？

机器人控制通常需要稳定频率，例如 5-10Hz 或更高。视觉 token 数越多，Transformer 推理越慢。 TokenLearner 用学习到的注意力权重把大特征图压成少量 token，让模型保留关键任务信息，同时降低计算量。

它和 ViT 的 CLS token 一样吗？

不完全一样。CLS token 通常是一个全局汇聚标记，而 TokenLearner 可以产生多个任务相关 token， 每个 token 可能关注不同区域或不同语义。它更像多个可学习的信息汇聚器。

256 bins：把连续动作变成分类/token 预测

机器人动作天然是连续值，例如末端执行器在 x/y/z 方向移动多少、旋转多少、夹爪开合多少。 RT-1 的处理方式是把每个动作维度离散化成 256 个区间，让模型输出分类分布。

为什么不直接回归连续动作？

直接用 MSE 回归容易遇到“多模态动作平均”问题。比如同一个状态下，向左绕过障碍和向右绕过障碍都可能正确， 回归模型可能学出中间值，结果反而撞上障碍。

离散化后，动作预测变成分类问题。softmax 分布可以保留多个高概率候选，训练也更接近 token prediction 范式。

注意： 256 bins 不是没有代价。它会引入量化误差，而且如果动作维度很多，动作组合空间会非常大。

数据 Pipeline：从 episode 到训练 batch

机器人数据通常不是普通图像分类数据。它是轨迹数据：一个 episode 包含多个 step， 每个 step 包含 observation、action、language instruction、状态和终止标记。

图像处理

resize、crop、归一化、颜色增强。注意不要破坏“红色杯子”这类语言与视觉属性的对应关系。

动作处理

统计每个动作维度范围，裁剪异常值，再映射到 256 bins。不同机器人动作空间需要额外标准化。

序列处理

轨迹长度不同，需要 sample index、padding、mask、frame stack 或 action horizon 设计。

推理流程：从指令到机器人动作

训练时模型学习预测专家动作；部署时，每个控制 step 输入当前图像和语言指令，输出动作 token， 再解码成连续控制命令发给机器人。

观测

机器人获取当前 RGB 图像、状态和固定或动态语言指令。

编码

语言嵌入生成 FiLM 参数，视觉特征经过 EfficientNet 和 TokenLearner 得到少量视觉 token。

预测

Transformer 根据视觉 token、状态和历史动作输出每个动作维度的 256-bin 分类分布。

执行

选择 bin，反离散化为连续动作，发送到控制器。下一个时间步重复这个闭环。

学 RT-1 不能只记“用了什么模块”，更要能解释为什么这样设计、代价是什么、后来模型为什么要改。

最小代码片段：把核心机制写成可理解的形状

下面代码不是完整 RT-1 复现，而是帮助你把三个关键机制落实到张量操作：FiLM、动作离散化、RLDS/episode 数据结构。

1. FiLM 最小实现

import torch
import torch.nn as nn

class FiLMLayer(nn.Module):
    def __init__(self, visual_dim: int, language_dim: int):
        super().__init__()
        self.to_gamma = nn.Linear(language_dim, visual_dim)
        self.to_beta = nn.Linear(language_dim, visual_dim)

    def forward(self, visual_feature, language_embedding):
        # visual_feature: (B, C, H, W)
        # language_embedding: (B, D)
        gamma = self.to_gamma(language_embedding).unsqueeze(-1).unsqueeze(-1)
        beta = self.to_beta(language_embedding).unsqueeze(-1).unsqueeze(-1)
        return gamma * visual_feature + beta

2. 256-bin ActionTokenizer 最小实现

import numpy as np

class ActionTokenizer:
    def __init__(self, low=-1.0, high=1.0, bins=256):
        self.low = low
        self.high = high
        self.bins = bins
        self.width = (high - low) / bins

    def encode(self, value):
        value = np.clip(value, self.low, self.high)
        idx = np.floor((value - self.low) / self.width).astype(int)
        return np.clip(idx, 0, self.bins - 1)

    def decode(self, idx):
        idx = np.clip(idx, 0, self.bins - 1)
        return self.low + (idx + 0.5) * self.width

tok = ActionTokenizer()
idx = tok.encode(0.254)
decoded = tok.decode(idx)

面试问答：D99 必须能讲清楚的题

Q1：RT-1 的完整架构是什么？

RT-1 输入 RGB 图像、语言指令、机器人状态和历史动作。图像经过 EfficientNet 提取视觉特征， 语言通过 FiLM 生成通道级调制参数注入视觉 backbone。TokenLearner 将空间视觉 token 压缩成少量关键 token， Transformer 建模上下文并预测离散动作 token，最后反离散化为机器人动作。

Q2：FiLM 的作用是什么？为什么不用简单拼接？

FiLM 让语言在视觉特征提取阶段就产生影响。简单拼接通常发生在后期融合，语言无法改变视觉 backbone 对特征的关注方式。 FiLM 通过 γ·F+β 调制视觉通道，轻量且适合实时控制。

Q3：TokenLearner 解决什么问题？

它解决视觉 token 太多导致 Transformer 推理慢的问题。它学习多个空间权重，把原始视觉特征汇聚成少量任务相关 token， 保留关键信息同时降低计算量。

Q4：256 bins 的优缺点是什么？

优点是把连续控制变成分类问题，训练稳定，能一定程度表达多模态动作分布，也方便和 token prediction 范式衔接。 缺点是有量化误差，动作维度增加会带来组合空间问题，精细控制可能受限。

D99 → D100：为什么 RT-1 会引出 RT-2

RT-1 建立了 VLA 的基本闭环，但它仍然是一个偏“专用机器人策略”的模型。D100 学 RT-2， 不是因为 RT-1 不重要，而是因为 RT-2 试图解决 RT-1 的核心瓶颈：开放世界语义泛化。

RT-1 已经解决了什么

  • 语言条件机器人操作可以端到端训练。
  • Transformer 可以处理多任务控制上下文。
  • 动作离散化可以把连续控制转成分类/token 问题。
  • 大规模真实机器人数据能显著提升泛化。

RT-1 仍然留下什么问题

  • 语义知识主要来自机器人数据，互联网视觉语言知识迁移不足。
  • 面对训练数据中没有的抽象指令或常识关系，能力有限。
  • 模型结构是专用策略网络，不是通用 VLM。
  • 跨任务、跨场景、跨 embodiment 的扩展仍然依赖更多机器人数据。
D100 的核心问题： 如果把动作也表示成 token，能不能让一个预训练 VLM 直接输出机器人动作？ RT-2 的答案是：可以，而且这样能把 VLM 的语义知识迁移到机器人控制中。
