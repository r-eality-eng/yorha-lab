RT-1、RT-2、Gato：三种 VLA 设计哲学

D103 的任务不是再学一篇新论文，而是把前三天的知识系统化： RT-1 是专用优化，RT-2 是知识迁移，Gato 是统一建模。真正的能力是看懂设计取舍，并能为项目选型。

学习目标：把论文知识变成设计判断

学完 D103，你应该不只是会复述三个模型，而是能回答“在什么场景下选哪种思路、为什么、代价是什么”。

RT-1

专用优化

为机器人控制效率和稳定性设计，适合任务固定、实时要求高的场景。

RT-2

知识迁移

把预训练 VLM 的视觉语言知识迁移到动作输出，适合语义开放任务。

Gato

统一建模

把多模态多任务统一成序列建模，适合 generalist agent 思想研究。

一句话主线： RT-1 深度优先，RT-2 借力预训练，Gato 广度优先。三者不是简单谁替代谁，而是代表不同设计取舍。

三种设计哲学：不是谁绝对更好，而是目标不同

RT-1

专用优化派

目标是让真实机器人稳定执行语言条件任务。设计围绕实时控制、视觉压缩、动作预测展开。

  • 优先级：控制效率
  • 关键词：FiLM、TokenLearner、256 bins
  • 适合：固定机器人任务
RT-2

知识迁移派

目标是把 VLM 预训练知识迁移到机器人动作，让模型理解更开放的语言和视觉概念。

  • 优先级：语义泛化
  • 关键词：VLM、action token、co-fine-tuning
  • 适合：开放语言任务
Gato

统一建模派

目标是用一个模型处理多种任务和模态，验证所有智能行为能否统一为 token 序列。

  • 优先级：任务广度
  • 关键词：unified tokenization、604 tasks
  • 适合：通用智能体研究

视觉处理深拆：三者到底在“看”什么

视觉模块不是简单的图片编码器，它决定了模型更擅长控制细节、开放语义，还是跨任务统一表示。 D103 要掌握的关键是：同样输入图像，三个模型会把图像压缩成完全不同的中间对象。

FiLM-EfficientNet 的直觉

RT-1 的视觉目标是服务机器人动作，不是开放世界问答。语言指令通过 FiLM 调制视觉特征： 同一张桌面图像，在“拿红杯子”和“推蓝方块”两条指令下，应该激活不同区域。

TokenLearner 再把密集视觉特征压成少量 token，减少 Transformer 后续计算量。这个设计牺牲一部分通用语义， 换来更好的实时性和机器人控制稳定性。

VLM 视觉编码的价值

RT-2 的视觉模块来自预训练 VLM，因此图像不是只被看成控制信号，还会被看成语义对象、关系和常识线索。 这就是为什么它能处理“拿起灭绝动物旁边的物体”这类需要语言知识迁移的任务。

代价也很直接：视觉编码器和语言模型规模大，自回归动作生成慢，部署时对显存、延迟和算力要求更高。

高分表达： RT-2 并不是让机器人数据从零学会语义，而是把 VLM 已经学到的视觉语言知识改造成可输出动作的能力。 所以它的视觉处理天然更偏“语义理解”，不是纯粹的低层控制特征。

统一 token 的收益和代价

Gato 的思路是把图像、文本、动作、奖励等全部变成 token 序列。好处是架构统一，所有任务都可以交给同一个 Transformer 做 next-token prediction。

但统一 tokenization 往往会带来信息损失和任务竞争：视觉细节可能被离散化压缩，多任务训练中机器人控制信号也可能被其他任务稀释。

容易误解： Gato 的“统一”不是免费午餐。统一接口降低了系统复杂度，但不保证每个具体机器人任务都达到专用模型的精度和稳定性。

动作生成深拆：为什么 RT-1 快，RT-2 懂，Gato 广

VLA 的动作头决定了模型如何从“理解场景”变成“控制机器人”。三者最核心的工程差异，往往就在动作表示和动作解码方式上。

问题RT-1RT-2Gato
动作如何表示每个动作维度离散成 bins，再由专用头预测动作被编码成 VLM 词表里的特殊 token动作和其他模态一起变成统一 token
动作如何生成多个动作维度偏并行输出，延迟低像生成文本一样逐 token 输出动作在统一序列里预测下一个 token
核心优势实时、稳定、部署简单动作生成能借用语言语义和视觉常识接口统一，适合研究跨任务迁移
核心代价难处理训练外开放语义模型大、推理慢、动作延迟高单任务控制精度可能被多任务目标稀释

设计哲学三角定位

三者可以放在一个设计三角里：效率、语义泛化、任务通用性。实际项目往往是在这三者之间取舍。

训练流程对比

RT-1：机器人数据监督学习

真实机器人演示数据，输入图像/语言/状态，目标是离散动作分类。训练重点是控制策略本身。

RT-2：VLM + Co-fine-tuning

加载预训练 VLM，混合机器人动作数据和视觉语言数据，既学动作 token，又保留 VLM 语义能力。

Gato：多任务 next-token prediction

把 604 种任务统一成 token 序列，用同一个因果 Transformer 预测下一个 token。

训练难点：三者不是换个 loss 那么简单

从论文阅读走向复现时，最容易低估的是训练数据、采样策略、损失平衡和动作标准化。这里把三者的训练风险放在一起看。

RT-1

机器人数据质量决定上限

监督学习流程相对直接，但数据分布窄、动作标注噪声、相机视角变化都会直接影响策略稳定性。

  • 关键风险：真实机器人演示覆盖不足。
  • 优化方向：数据清洗、任务均衡、动作 bins 校准。
RT-2

Co-fine-tuning 要防止遗忘

如果机器人数据占比过高，VLM 原有问答和语义能力会退化；如果图文数据占比过高，动作学习又不充分。

  • 关键风险：动作能力和语义能力互相拉扯。
  • 优化方向：混合比例、loss 权重、动作 token 设计。
Gato

多任务采样决定学到什么

604 种任务统一训练时，样本量大的任务可能主导梯度，稀有任务被淹没；任务之间还可能存在目标冲突。

  • 关键风险：任务竞争和梯度冲突。
  • 优化方向：课程学习、任务重加权、adapter/MoE。
工程记忆法： RT-1 难在“机器人数据够不够好”，RT-2 难在“机器人动作和 VLM 知识怎么共存”，Gato 难在“这么多任务怎么公平且有效地一起学”。

推理流程对比：速度和能力从这里分叉

模型推理路径速度倾向主要瓶颈
RT-1图像/语言 → 专用策略 → 动作最快语义泛化有限
RT-2图像/语言 → VLM → 自回归动作 token较慢大模型 + 多步解码

工程直觉： 机器人真实部署通常更在意 Hz、延迟、失败恢复和控制稳定性；研究 generalist agent 更在意任务覆盖和统一接口。

选型决策框架：面试和项目都能用

如果你最关心实时控制

优先 RT-1 或类似专用策略。先保证闭环能稳定跑，再考虑语义泛化。

如果你最关心开放语言理解

优先 RT-2/OpenVLA 风格。用 VLM 的语义知识解决新物体、新表达、新组合问题。

如果你最关心通用智能体研究

借鉴 Gato。重点研究统一 tokenization、多任务学习、跨模态迁移。

如果你想设计下一代 VLA

组合思路：VLM 负责语义，专用 action expert 负责连续高频动作，多数据集训练提供泛化。

class RT1Policy:
    def act(self, image, instruction, robot_state):
        visual = film_efficientnet(image, instruction)
        tokens = token_learner(visual)
        return action_head(tokens, robot_state)  # 专用动作预测

class RT2Policy:
    def act(self, image, instruction):
        prompt = build_prompt(instruction)
        action_tokens = vlm.generate(image, prompt)  # VLM生成动作token
        return decode_action_tokens(action_tokens)

class GatoAgent:
    def step(self, multimodal_sequence):
        tokens = unified_tokenizer(multimodal_sequence)
        next_tokens = transformer.generate(tokens)  # 任意任务的下一个token
        return interpret_by_task(next_tokens)

涌现能力：为什么 RT-2 有，而 RT-1 基本没有

面试里最容易被追问的是“RT-2 为什么能做没在机器人数据里见过的语义任务”。答案不是动作头更神奇，而是大规模 VLM 预训练知识被迁移到了动作生成。

RT-2 的涌现链路

  1. VLM 在大规模图文数据中学到物体、属性、关系和常识。
  2. Co-fine-tuning 把机器人动作变成 VLM 能生成的 token，同时保留一部分原有语义能力。
  3. 推理时，抽象语言会先触发 VLM 里的语义关联，再映射成机器人动作 token。

RT-1 的能力边界

  1. RT-1 主要依赖机器人演示数据和较轻量视觉预训练。
  2. 训练目标集中在已见过的语言条件控制任务。
  3. 如果指令需要互联网级语义常识，模型缺少足够来源去推理。
一句话总结： 涌现能力 = 大规模预训练知识 + 不把知识洗掉的迁移方法 + 可被动作 token 调用的输出接口。

下一代 VLA 设计：不是三选一，而是组合优点

D103 最终要形成设计能力：真实系统通常不会原样照搬 RT-1、RT-2 或 Gato，而是把它们的优点组合起来。

设计目标可采用方案来自哪条思想
保持开放语义理解保留 VLM 基座，训练中混合图文任务RT-2

面试问答：D103 的核心就是讲 trade-off

高分回答模板： RT-1、RT-2、Gato 代表三种不同设计哲学。RT-1 是专用优化派，目标是让真实机器人高效稳定控制； RT-2 是知识迁移派，目标是把预训练 VLM 的语义和常识迁移到机器人动作； Gato 是统一建模派，目标是把多模态多任务都变成 token 序列交给一个 Transformer。 选型时不能只看谁更新，而要看实时性、语义开放性、任务广度和部署成本。
Q1：RT-1、RT-2、Gato 的核心区别是什么？

RT-1 是专用机器人模型，重控制效率；RT-2 是 VLM-based VLA，重语义泛化；Gato 是 generalist agent，重多任务统一建模。

Q2：真实机器人项目里怎么选？

任务固定且实时要求高，选 RT-1 类专用策略；语言和物体开放，选 RT-2/OpenVLA 类；研究多任务通用智能体，借鉴 Gato；下一代系统可组合 VLM 和专用动作专家。

Q3：Gato 为什么不是 RT-2 的替代品？

Gato 追求任务广度和统一接口，而 RT-2 追求把 VLM 知识迁移到机器人操作。Gato 的思想有启发，但真实机器人控制仍需要更强动作建模和部署优化。

Q4：这三者对后续 VLA 的共同启发是什么？

RT-1 说明专用控制和数据规模重要；RT-2 说明 VLM 知识迁移重要；Gato 说明统一 tokenization 和多任务训练重要。后续模型通常在这三者之间组合。

Q5：为什么 RT-2 有涌现能力，而 RT-1 没有？

RT-2 的涌现能力主要来自互联网规模 VLM 预训练。模型已经学到物体、属性、关系和常识，co-fine-tuning 只是让这些知识能通过动作 token 表达出来。RT-1 更依赖机器人演示数据，数据里没有的抽象语义很难凭空出现。

Q6：三者各自怎么改进？

RT-1 可以增强预训练视觉和数据多样性；RT-2 可以用蒸馏、量化、并行动作生成或 Flow Matching 降低延迟；Gato 可以用更强 scaling、MoE、adapter 或任务重加权缓解多任务冲突。

自测清单：能不能形成系统判断

1. 用一句话概括三者设计哲学。
RT-1 是专用优化，RT-2 是知识迁移，Gato 是统一建模。
2. 为什么不能简单说 Gato 比 RT-1/RT-2 更先进？
因为 Gato 追求多任务通用性，不一定在真实机器人单任务控制、实时性和精度上优于专用 VLA。
3. 如果设计下一代 VLA，你会借鉴哪三点？
借鉴 RT-1 的控制效率和数据 pipeline，RT-2 的 VLM 知识迁移，Gato 的统一 tokenization 和多任务数据混合。
