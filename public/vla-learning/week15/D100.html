RT-2：让 VLM 直接输出机器人动作

RT-2 的核心不是又发明一种动作离散化，而是把机器人动作放进视觉语言模型的 token 生成范式里： 图像和指令进入 VLM，模型像生成文本一样生成动作 token，再解码为机器人控制。

学习目标：D100 要抓住的三个核心问题

D99 讲的是 RT-1 如何搭建专用机器人策略，D100 讲的是 RT-2 如何把 VLM 的视觉语言知识迁移到动作生成。 这一天的重点是范式变化，而不是单独记一个动作 tokenizer。

问题 1

为什么需要 RT-2？

RT-1 依赖机器人数据学习语义和动作，开放世界知识不足。RT-2 借助预训练 VLM 弥补这个短板。

问题 2

动作如何变成语言？

连续动作被离散成 token，并放入 VLM 的输出序列中，用 next-token prediction 生成。

问题 3

代价是什么？

RT-2 获得语义泛化，但自回归生成动作较慢，离散动作仍有精度和效率问题。

一句话抓主线： RT-2 不是“更大的 RT-1”，而是把机器人动作纳入 VLM 的 token 语言，让模型用互联网视觉语言知识指导机器人控制。

范式转折：从专用策略到 VLM→VLA

RT-1 的路线是“为机器人任务训练一个专用模型”。RT-2 的路线是“拿一个已经学过海量图文知识的 VLM， 再教它输出机器人动作”。这就是 VLM→VLA 的核心转折。

RT-2 架构：把 VLM 改造成 VLA

RT-2 保留 VLM 的视觉-语言理解能力，同时把机器人动作表示成特殊 token，让同一个模型既能回答视觉语言问题，也能输出控制命令。

教学抽象说明： 本页将 RT-2 简化为“图像 + 指令 → VLM → 动作 token → 连续动作”的主线。 真实 RT-2 使用的基座模型、tokenizer 扩展方式、动作维度和训练数据混合细节应以论文为准。

点击架构图中的模块，可以查看它在 RT-2 中承担的作用。

两个基座模型：PaLI-X 与 PaLM-E

RT-2 不是单一模型实例，而是验证了“不同 VLM 基座都可以被改造成 VLA”。论文中重要的两个版本是 RT-2-PaLI-X 和 RT-2-PaLM-E。

维度 RT-2-PaLI-X RT-2-PaLM-E
基座特点 强视觉语言模型，偏视觉理解和多模态任务 具身多模态语言模型，偏语言推理和 embodied reasoning
规模印象 更大，视觉能力强 相对更小，但语言推理和具身任务联系更强

共同点 都说明：预训练 VLM 可以通过动作 token 和 co-fine-tuning 变成 VLA。
面试表达： 讲 PaLI-X 和 PaLM-E 时，不需要背每个参数细节，重点是说明 RT-2 的贡献不依赖某个单一 backbone， 而是验证了 VLM→VLA 这条路线本身可行。

核心创新：动作 = 语言 Token

RT-2 的动作表示可以理解为：先把连续动作离散化，再把离散编号包装成特殊 token， 让 VLM 像生成文字一样生成机器人动作。

动作 token 化流程

  1. 将每个连续动作维度裁剪到预设范围。
  2. 把每个维度映射到 0-255 的离散 bin。
  3. 把 bin 编号变成特殊 token，例如 <act_160>。
  4. VLM 自回归生成这些 token。
  5. 把 token 解码回连续动作，发给机器人。

一个 RT-2 输出序列长什么样？

User: pick red cup → <act_160> <act_114> <act_193> <act_132> <act_127> <act_140> <act_255>
关键区别： RT-1 的动作预测更像专用动作分类头；RT-2 的动作预测则复用 VLM 的语言建模接口。 这就是为什么 RT-2 能把 VLM 的预训练知识迁移到机器人控制里。

词表扩展：动作 token 如何进入 VLM

RT-2 的动作 token 不应该和普通数字 token 混淆。更清晰的理解是：在原有 VLM 词表之外，增加一段专门表示动作 bin 的 token ID 区间。

为什么不用普通数字 token？

如果直接输出文本里的 “3” 或 “128”，模型很难区分这是自然语言数字，还是动作 bin。 独立动作 token 区间可以避免语义冲突。

为什么需要输出格式约束？

推理时通常希望模型只生成合法动作 token，而不是自由生成自然语言。 因此可以限制 logits 范围、使用特殊起止符，或通过 prompt 约束输出格式。

自回归生成：为什么 RT-2 强但可能慢

RT-2 像生成一句话一样生成动作序列。每生成一个动作 token，都要基于前面已经生成的 token 再预测下一个。 这带来表达统一性，也带来推理延迟。

Co-fine-tuning：既学动作，又保留 VLM 能力

如果只用机器人数据微调 VLM，模型可能学会动作，却忘掉原来的视觉语言知识； 如果只保留 web/VQA 数据，模型又不会控制机器人。Co-fine-tuning 的思想是混合训练两类数据。

只用机器人数据

动作学习更直接，但数据量小，容易破坏 VLM 原本语义能力，出现灾难性遗忘。

只用 Web/VQA 数据

保持语义和视觉问答能力，但不会学到机器人动作 token 的含义。

Co-fine-tuning

用混合数据同时优化语言/视觉能力和动作输出能力，是 RT-2 保持涌现能力的关键。

训练损失结构：文本 CE + 动作 CE

Co-fine-tuning 不只是“把两种数据放一起”。更准确地说，不同样本在不同 token 位置计算不同的 cross-entropy loss： 视觉语言数据保持 VLM 的文本生成能力，机器人数据训练动作 token 生成能力。

简化公式： L_total = λ_text · L_text + λ_action · L_action。 其中 L_text 来自普通文本/视觉语言 token 的预测，L_action 来自动作 token 位置的预测。

λ 怎么理解？

它代表两类任务的训练权重。机器人数据权重过高可能损害 VLM 原能力；文本/VQA 权重过高则动作学不充分。 实际训练中，数据采样比例和 loss 权重都属于关键超参数。

为什么只在动作位置算动作 loss？

因为动作 token 是目标控制输出。普通 prompt、图像 token 或文本上下文只是条件，不应该被当作动作预测目标。 这和语言模型中“在目标 token 位置计算 CE”是同一个思想。

涌现能力：RT-2 为什么能做训练集中没直接出现的事

RT-2 最有影响力的地方，是展示了 VLM 预训练知识可以迁移到机器人动作。 例如模型未必在机器人数据里见过“已灭绝动物”这样的指令，但 VLM 可能知道恐龙属于已灭绝动物。

RT-2 的历史意义在于证明 VLM→VLA 可行。后续很多工作不是推翻 RT-2，而是在解决它留下的工程和表示问题。

最小代码片段：动作 token 和自回归生成

下面代码只展示 RT-2 思路的最小抽象：连续动作转特殊 token，以及模型逐个生成动作 token。

1. 动作 token 化

class RT2ActionTokenizer:
    def __init__(self, bins=256, low=-1.0, high=1.0):
        self.bins = bins
        self.low = low
        self.high = high
        self.width = (high - low) / bins

    def encode_value(self, value):
        idx = int((max(self.low, min(self.high, value)) - self.low) / self.width)
        idx = max(0, min(self.bins - 1, idx))
        return f"<act_{idx}>"

    def decode_token(self, token):
        idx = int(token.replace("<act_", "").replace(">", ""))
        return self.low + (idx + 0.5) * self.width

面试问答：D100 必须能讲清楚的题

高分回答模板： RT-2 证明了 VLM→VLA 的可行性：它把连续机器人动作离散成特殊 token， 通过 co-fine-tuning 让预训练 VLM 学会生成动作，同时保留互联网图文预训练带来的语义知识。 它最大的价值是带来语义泛化和涌现能力；最大的工程挑战是推理速度、模型规模和动作表示精度。 后续 OpenVLA、π0、π-FAST 分别从开源实用化、连续快速动作生成和高效动作 tokenization 方向继续改进。
Q1：RT-2 的核心创新是什么？

RT-2 的核心创新是把预训练 VLM 扩展成 VLA，让模型把机器人动作当作特殊 token 生成。 它不是从零训练一个专用策略，而是通过 co-fine-tuning 让 VLM 同时保留视觉语言知识并学会输出动作。

Q2：为什么 RT-2 会有涌现能力？

因为 RT-2 的基座 VLM 已经从大规模图文数据中学到了语义、常识和视觉概念。机器人数据教会模型把这些语义映射到动作 token， 所以在遇到抽象指令或训练中没直接出现的组合时，可能利用预训练知识完成任务。

Q3：RT-2 相比 RT-1 最大的代价是什么？

主要代价是推理速度和工程成本。RT-2 模型更大，并且动作 token 通常自回归生成，控制频率可能低于专用策略。 此外，训练数据混合比例、动作 token 设计和模型部署都更复杂。

Q4：动作 token 和文本 token 是一回事吗？

它们在模型接口上都是 token，但语义不同。文本 token 表示自然语言片段，动作 token 表示离散化后的控制值。 RT-2 的关键是让模型在同一个序列建模框架下学习这两类 token 的关系。

自测清单：看完能不能过关

1. 用一句话解释 RT-2。
RT-2 是把预训练 VLM 微调成 VLA 的方法，让模型像生成语言一样生成机器人动作 token，从而把视觉语言知识迁移到机器人控制。
2. RT-2 为什么不是简单的“RT-1 加大模型”？
因为 RT-2 的关键范式是复用 VLM 的 next-token prediction 和预训练知识，让动作成为语言模型输出序列的一部分，而不是只扩大专用机器人策略网络。
3. Co-fine-tuning 解决什么问题？
它在机器人动作数据和 web/VQA 数据之间做混合训练，让模型既学会动作输出，又尽量不遗忘原有视觉语言能力。
