OpenVLA 总架构：从图像和指令到 7 维动作

OpenVLA 可以理解为一个开源 VLA 组合系统：用开源视觉编码器替代闭源大视觉模型，用 Llama2-7B 承担语言和动作生成。

一句话主线：OpenVLA 用双视觉编码器补足语义和空间，用 projection 把视觉 token 对齐到 Llama2 维度，再让 Llama2 像生成文本一样生成 7 个动作 token。

Prismatic 双视觉编码器：what + where

为什么单编码器不够

只用语义编码器，模型知道“这是杯子”，但可能不知道把手的精确位置；只用空间编码器，边缘和局部结构清楚，但未必知道哪些区域在语义上重要。

  • SigLIP：知道是什么。
  • DINOv2：知道在哪里。
  • 融合后：知道要抓什么，也知道大概从哪里抓。

机器人操作的直觉

抓取不是图像分类。机器人要理解“红杯子”这种语义对象，也要定位把手、边缘、遮挡、桌面接触点等空间细节。Prismatic 的设计就是把这两类能力显式组合。

SigLIP 与 DINOv2：两个编码器各自解决什么

SigLIP：语义对齐

SigLIP 来自图文对比学习，核心能力是把图像区域和语言概念对齐。对机器人而言，它帮助模型理解“红杯子”“把手”“盘子旁边”等语义对象。

logits = image_features @ text_features.T
loss = sigmoid_pairwise_loss(logits, labels)
记忆法：SigLIP 回答 what：这是什么物体，它和语言指令中的哪个概念相关。

DINOv2：空间结构

DINOv2 通过自监督蒸馏学到鲁棒视觉特征，通常对边界、局部结构、物体区域有更好的空间对应。对机器人而言，这对抓取点和操作位置很重要。

student = encoder(local_view)
teacher = ema_encoder(global_view)
loss = distillation_loss(student, teacher)
记忆法：DINOv2 回答 where：目标在哪里、边界在哪里、局部结构怎么分布。
任务只看语义的问题只看空间的问题双编码器收益
抓杯子把手知道是杯子，但把手定位不准看到边缘，但不知道把手语义重要知道抓哪个语义部位，也保留局部位置
把红块放到盘子上红块语义可识别，但相对位置不稳空间关系清楚，但颜色/对象语义弱同时利用颜色语义和几何位置

CLIP vs SigLIP：为什么 Sigmoid Loss 有价值

OpenVLA 使用 SigLIP，不只是因为它强，更因为它提供稳定的图文语义对齐。机器人需要知道图像中的哪个物体对应语言指令。

维度CLIP / InfoNCESigLIP / Sigmoid
训练目标batch 内 softmax 分类每个 image-text pair 独立二分类
负样本关系所有负样本互相竞争每个负样本独立判断
工程直觉从一堆文本中选正确文本判断这对图文是否匹配
对 OpenVLA 的价值提供语义对齐基线稳定提供物体、属性、关系语义
# CLIP: batch 内 softmax
logits = image_features @ text_features.T
loss = cross_entropy(logits, labels)

# SigLIP: pairwise sigmoid
logits = image_features @ text_features.T
loss = sigmoid_binary_loss(logits, pair_labels)

DINOv2 自蒸馏：为什么它更像空间结构专家

DINOv2 不依赖文本语义，而是从图像自身学习稳定视觉结构。它通过 student/teacher 自蒸馏，让局部视图和全局视图形成一致表征。

机器人意义：DINOv2 帮助模型保留边界、局部结构、物体区域和视角鲁棒性，对抓取点、放置位置、避障都很关键。

特征融合：patch-level 特征对齐到 Llama2 维度

OpenVLA 不是把整张图压成一个向量，而是保留 patch-level visual tokens。这样 Llama2 能看到一组视觉 token，而不是单个全局摘要。

Projection

投影、拼接、MLP，得到 Llama2 可接收的 visual tokens。

Prismatic 维度流：projection 不是简单降维

视觉编码器输出和 Llama2 hidden size 不天然一致，projection 的作用是把视觉表征翻译到 Llama2 的 token embedding 空间。

Llama2 作为语言模型骨干：把动作当成可生成 token

OpenVLA 的关键范式是让 Llama2 接收 visual tokens 和 language tokens，然后自回归生成 action tokens。动作不再是传统控制器输出，而是语言模型输出空间的一部分。

Action Tokenizer：256 bins 如何影响动作精度

交互理解：bins 和量化误差

假设动作范围 [-1,1]，bin width 约 0.0078，最大量化误差约 0.0039。

离散化流程

  1. 把连续动作裁剪到固定范围。
  2. 映射到 0 到 bins-1 的整数。
  3. 转成 action token id。
  4. 推理时反解码回连续动作。

推理与部署：6Hz 够不够，瓶颈在哪里

OpenVLA 的推理速度示例约为 170ms/step，也就是大约 6Hz。对低速精细操作可能够用，对高速动态任务通常不够。

可接受场景

低速抓取、桌面整理、实验室演示、离线评估。

风险场景

高速避障、动态抓取、强实时闭环、接触变化很快的任务。

优化方向

INT8/INT4 量化、KV cache、speculative decoding、更少动作 token、连续动作生成。

推理延迟分解：为什么 7 个 action tokens 会慢

动作是 7 个 token 自回归生成，每个 token 都依赖前面结果，因此延迟会累积。控制系统需要低延迟，而语言模型天然更偏上下文建模和吞吐。

OpenVLA 改进路线图

目标改进方向可能代价
提升语义泛化加入 web/video 预训练或更强 VLM训练成本变高，数据噪声增加
提升空间精度更新视觉编码器、加入深度/多视角传感器和输入 pipeline 更复杂
提升控制频率量化、蒸馏、减少 action tokens、连续生成可能损失语义能力或动作精度

最终判断：OpenVLA 的意义不是它已经是最终答案，而是它提供了一个开源、可复现、可改造的 VLA 基线。

场景选择器：什么时候更像 OpenVLA，什么时候更像 RT-2

推荐 OpenVLA：代码、权重和数据路线更开放，更适合复现、消融和工程改造。

面试问答：D106 的高频追问

Q1：请画出 OpenVLA 架构并解释数据流。

图像先进入 SigLIP 和 DINOv2，分别提取语义和空间特征；两路 patch features 经过 projection 和融合后变成 visual tokens；visual tokens 与语言 tokens 一起输入 Llama2-7B；模型自回归生成 7 个 action tokens，再解码为连续 7D 动作。

Q2：为什么 OpenVLA 要用 SigLIP + DINOv2？

机器人操作同时需要语义理解和空间定位。SigLIP 更擅长对象语义，DINOv2 更擅长局部结构和空间对应。双编码器是用开源模型组合出语义和空间的互补能力。

Q3：OpenVLA 只用机器人数据训练，不用 Web 数据，是优势还是劣势？

优势是数据分布更贴近机器人控制，OXE 公开可复现；劣势是互联网语义知识较弱，对完全新奇概念的泛化可能不如 RT-2。

Q4：OpenVLA 6Hz 够用吗？主要瓶颈是什么？

低速桌面操作可能够用，高速动态控制不够。主要瓶颈通常在 LLM 自回归解码多个 action tokens。
