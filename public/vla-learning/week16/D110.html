LoRA 原理：只训练低秩增量

LoRA 的关键是冻结原始权重 W，只训练低秩矩阵 A 和 B，让模型学到一个任务相关的增量 ΔW = B A。

优点

显存低、迭代快、保留预训练能力、适合中小数据任务适配。

代价

容量有限；如果任务与预训练分布差异很大，LoRA 可能不如全参数或分阶段微调。

关键超参

rank、alpha、dropout、target modules、学习率、训练步数。

Label Mask：只监督 action token

OpenVLA 微调最容易讲错的地方是 labels。更严谨的 CausalLM 式训练不是传入一个孤立的 [B, 7] labels，而是把 action tokens 拼到输入序列末尾，并只在 action 位置计算 loss。

input_ids = torch.cat([prompt_ids, action_token_ids])
labels = torch.full_like(input_ids, -100)
labels[-len(action_token_ids):] = action_token_ids

# padding时也要保持labels的padding位置为-100
# 不要手写token offset，使用当前OpenVLA版本的ActionTokenizer。
如果 input_ids 末尾没有 action tokens，验证时取 outputs.logits[:, -7:, :] 就不代表动作位置；此时 token accuracy 和 loss 都可能没有教学意义。

训练流程：从数据到 checkpoint

训练曲线诊断：loss 下降不等于任务成功

曲线现象诊断优先处理
train/val loss 都下降训练正常，但仍需看闭环成功率继续评估 success rate 和失败类型
train loss 降，val loss 升过拟合或验证分布不同早停、增强、降低 rank/lr、增加验证集隔离
loss 不下降学习率、labels、mask、action tokenizer 或数据对齐问题先查数据和 label mask，再调 lr
loss 震荡学习率偏高、batch 太小、数据噪声大降低 lr、增大 accumulation、梯度裁剪
val loss 好但成功率差离线指标和闭环指标不一致检查反归一化、控制频率、gripper 和评估 prompt

Checkpoint：不能只按 val loss 选模型

VLA 微调的最终目标是闭环成功率。一个 checkpoint 可能 val loss 更低，但 gripper 时机、动作尺度或真实控制稳定性更差。

维度应记录指标判断方式
训练稳定性train loss、grad norm、learning rate无持续震荡、无梯度爆炸
离线验证val loss、action token accuracyheld-out episode 上稳定改善
连续动作xyz/rpy MAE、gripper error、action saturation关键动作维度误差下降
闭环任务success rate、partial success、failure type目标任务提升且泛化任务不明显下降
部署代价latency、memory、merge consistencyadapter 合并前后结果一致

面试问答：D110 高频问题

1. OpenVLA 微调完整流程是什么？
准备任务数据，校验图像/动作/指令对齐；选择 LoRA、冻结、全参数或分阶段微调；配置 target modules 和训练超参；训练时监控 loss、grad norm、val loss；评估 success rate、action error、失败类型和延迟；最后保存或合并 adapter 并做部署验证。
2. 为什么 loss 下降但成功率不升？
可能是 label mask 错、动作反归一化错、训练/推理 prompt 不一致、验证集泄漏或分布不匹配、gripper 标签噪声、离线动作误差不能代表闭环稳定性、控制频率或环境随机性导致失败。
3. LoRA 和全参数微调如何选择？
数据少、算力有限、需要快速迭代时优先 LoRA；数据充足、任务分布差异大、追求最高性能时可考虑全参数或分阶段微调。最终选择必须由 held-out success rate、失败类型和部署成本决定。
