数据增强：不是所有图像增强都适合机器人

增强类型选择

颜色增强通常适合提升光照鲁棒性，但要避免改变“红杯/蓝杯”等颜色语义。

动作一致性原则

机器人数据增强必须问一个问题：增强后的图像对应的动作标签是否仍然正确。水平翻转、旋转、裁剪这类几何增强可能改变动作方向，不能像普通分类任务那样随便使用。

# 原则：增强图像后，如果空间关系改变，
# action也要同步变换；做不到就不要用该增强。
image_aug, action_aug = transform_image_and_action(image, action)

Prompt 工程：模板稳定性也是实验变量

In: What action should the robot take to pick up the red cup?
Out:

短、直接，适合作为基线。缺点是对复杂任务和歧义场景约束不足。

In: The robot sees a tabletop scene. The target is the red cup.
What action should the robot take next?
Out:

加入场景和目标描述，适合多物体任务，但要保持训练/推理模板一致。

In: Move carefully toward the red cup and avoid the blue bowl.
What is the next robot action?
Out:

加入避障或安全约束，适合诊断模型是否能利用语言约束。

Prompt 实验不能只看单张图的输出，要看同一任务多 episode 的成功率方差、失败类型和动作抖动。

动作头设计：动作表示决定误差形态

动作头优势风险适合场景
离散 action token复用 LLM 生成范式量化误差、decode 串行OpenVLA 主线、可解释 token 分布
连续回归头动作更直接训练稳定性和多模态动作难处理精细控制、低延迟场景
混合动作头兼顾粗粒度和细粒度系统复杂度高高精度抓取、长程任务
不确定性头能识别低置信动作校准困难安全部署、人工接管

动作表示：ActionTokenizer、FAST、连续头怎么选

表示方式核心思想优势主要风险验证指标
官方 ActionTokenizer连续动作离散成 token，由 LLM 生成复现 OpenVLA 主线离散误差和自回归延迟token accuracy、连续动作 MAE、decode latency
连续回归头hidden state 直接回归动作低延迟、无离散化多模态动作难表达xyz/rpy MAE、smoothness、success rate
FAST tokenizer更高效地表示动作序列降低动作 token 负担需要对齐官方训练流程tokens/action、latency、success rate
Action chunking一次预测未来多步动作降低推理频率、动作平滑闭环反馈变慢chunk success、replan frequency、jerk
选择动作表示前，先确认瓶颈：decode 慢优先 FAST/chunking，动作精度差优先连续/混合头，部署安全差优先不确定性和动作平滑。

量化权衡：速度、显存和动作质量一起看

VLA 量化不能只报告 tokens/sec。动作 token 的微小偏差可能放大成抓取失败、碰撞或 gripper 时机错误。
量化方式目标风险验证重点
BF16/FP16基线、稳定显存高作为对照组
INT8平衡显存和质量硬件/库支持影响速度成功率、p99 延迟
INT4/NF4显著降低显存动作稳定性下降gripper、旋转、接触前动作
GPTQ/AWQ后训练量化需要代表性校准数据校准集覆盖任务分布

优缺点：把技术特点映射到落地风险

优势

端到端图像、语言、动作统一建模，开发接口简洁。
预训练先验利用视觉语言模型能力，数据效率更高。
模块化视觉编码器、LLM、动作头、LoRA/量化都可独立实验。

劣势

延迟高LLM decode 影响控制频率。
显存高7B 模型部署门槛高。
可解释性有限失败归因需要日志、视频和消融实验。
分布敏感新物体、新平台、复杂任务仍需微调。

改进路线：先定位瓶颈，再选手段

面试问答：D111 高频问题

1. 如何设计 OpenVLA 改进实验？
先定义瓶颈和指标，再做单变量实验。数据增强看泛化，Prompt 看模板稳定性，动作头看连续动作误差和成功率，量化看显存、延迟、动作质量和失败类型。
2. 量化后速度变快但成功率下降怎么办？
先定位下降来自 gripper、旋转、位置还是视觉误差；尝试 INT8 替代 INT4、混合精度、AWQ/GPTQ 校准、保留敏感模块高精度，并重新跑闭环评估。
3. 为什么几何增强有风险？
因为机器人动作和图像空间关系强绑定。水平翻转、旋转、裁剪可能改变目标相对位置，如果 action 没有同步变换，训练标签就变错。
