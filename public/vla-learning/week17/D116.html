三层架构总览

Level 3：VLM 推理层

推理层的核心不是输出一段漂亮文字，而是输出可验证、可执行、可重规划的结构化结果。

结构化输出

{
  "objects": [
    {"name": "bowl", "position": [x,y,z], "state": "dirty"}
  ],
  "subtasks": [
    {"id": 1, "skill": "pick", "target_object": "bowl"},
    {"id": 2, "skill": "place", "target_object": "sink"}
  ],
  "execution_order": [1, 2],
  "contingency_plans": [...]
}

为什么要结构化

可执行技能层能读取 skill、object、parameters
可检查能验证前置条件和依赖关系
可恢复失败后知道从哪个子任务重规划
可评估可以统计 subtask success 和 planning quality
不要假设 VLM 文字推理天然可靠。机器人系统需要 schema、约束检查、状态机和失败检测，把自然语言推理限制在可执行空间里。

任务图：把长任务拆成有依赖的子任务

节点

子任务或原子操作，如“捡垃圾”“放到水槽”。

边

顺序依赖、资源依赖或数据依赖，如必须先抓取再放置。

状态

pending、ready、running、completed、failed，用于调度和恢复。

Level 2：技能规划层

技能层把“子任务”翻译成机器人已有技能及参数。它不是底层动作控制器，而是计划和执行之间的接口。

技能状态机：把计划变成可控执行

IDLE等待任务
EXECUTING执行当前技能
RECOVERING失败恢复
COMPLETED技能序列完成
状态机的价值是把 VLM 的计划约束到可监控执行流程里。每个技能都有开始、执行、完成、失败和恢复路径。
from enum import Enum

class State(Enum):
    IDLE = "idle"
    EXECUTING = "executing"
    RECOVERING = "recovering"
    COMPLETED = "completed"
    FAILED = "failed"

Level 1：底层 Flow Matching 控制器

底层不是一次执行完整长任务，而是接收当前技能和参数，生成短 action chunk，并在 receding horizon 中执行。

层次化条件

conditions = {
  "vlm_semantic": vlm_embedding,
  "skill_params": skill_params,
  "proprioception": robot_state,
  "visual_state": visual_features,
}

生成时注意 device

device = conditions["proprioception"].device
a_t = torch.randn(batch, 4, 7, device=device)
t_tensor = torch.full((batch, 1), t, device=device)
velocity = controller(a_t, t_tensor, conditions)
a_t = a_t - velocity * dt

层次化训练策略

Phase 1

底层控制

大量遥操作数据训练 Flow Matching controller，学习基础运动技能。

Phase 2

技能规划

用技能标注数据学习子任务到技能和参数的映射。

Phase 3

推理层

用高质量任务分解示例训练 VLM reasoning 输出结构化计划。

Phase 4

端到端微调

使用差异学习率整体微调，控制高层遗忘和低层稳定性。

训练顺序的本质：先让“手”会动，再让“技能”会选，最后让“脑”会分解任务。反过来训练通常更不稳定。

长 Horizon 的两个关键机制：上下文和失败检测

上下文管理

长任务不能把所有历史都塞进 prompt。系统需要维护世界状态、任务进度、最近历史和摘要。

context = {
  "world_state": objects,
  "task_progress": completed / pending / failed,
  "recent_history": last_10_steps,
  "summary": compressed_memory,
}

失败检测

重规划必须有触发条件：物体丢失、位置不符、技能失败、新障碍、超时或安全约束触发。

need_replan = (
  object_missing or
  position_mismatch or
  skill_failed or
  timeout or
  safety_violation
)

评估指标：长任务不能只看最终成功率

指标衡量什么为什么重要
task success最终任务是否完成整体结果
subtask success每个子任务是否完成定位失败发生在哪一层
skill accuracy技能选择是否正确检查 skill planner
planning quality步骤是否合理、是否满足约束检查 reasoning layer
recovery success失败后是否恢复长任务鲁棒性关键
safety events碰撞、越界、超力、危险动作真实部署必须监控
不要背教学百分比。真实评估必须在同一机器人、同一任务集、同一数据规模、同一失败定义下比较。

π0 vs π0.5：能力差异

能力维度π0π0.5
任务复杂度单步/少步长 horizon、多阶段
推理能力较弱或隐式显式任务理解和分解
执行方式短 action chunk子任务 + 技能 + action chunk
错误恢复有限动态重规划
可解释性较弱可以查看计划、技能和失败点
推理开销更低更高，需要缓存和异步执行

面试表达：2分钟讲清 π0.5

π0.5 的核心是把 VLA 从短 horizon action generation 推进到 long-horizon task execution。它通常需要三层结构：高层 VLM reasoning 做任务分解和约束规划，中层 skill planner 把子任务映射成技能和参数，底层 π0-style controller 生成连续 action chunk，并通过失败检测和动态重规划形成闭环。
为什么不是一次输出长动作？长动作开环误差会累积，环境也会变化；更稳妥是短 chunk 执行和持续重规划。
为什么要任务图？表达子任务依赖、执行状态和重规划入口。
为什么要技能库？把自然语言目标约束到机器人可执行技能空间。
如何训练？底层控制、技能规划、推理分解分阶段训练，再小学习率端到端微调。
主要风险包括：VLM 计划幻觉、结构化输出解析失败、技能前置条件不满足、失败检测不可靠、重规划循环、推理延迟过高和安全约束缺失。

自测：确认你理解 D116

1. 为什么长 horizon 不是一次性输出很长动作？
因为环境会变化，开环误差会累积。更稳妥是高层持续规划，底层执行短 action chunk 并不断重新观察。
2. π0.5 三层分别做什么？
Reasoning 层做任务理解和分解；Skill 层选择技能和参数；Low-level 层生成连续动作并执行。
3. 任务图有什么用？
任务图表达子任务依赖、执行状态和失败重规划入口，使长任务可调度、可检查、可恢复。
4. 动态重规划什么时候触发？
目标物体消失、位置偏移、技能失败、新障碍、超时或安全约束触发时都可能需要重规划。
5. 评估 π0.5 为什么不能只看 success rate？
因为长任务失败可能发生在推理、技能选择、底层控制或恢复环节，需要 subtask success、skill accuracy、recovery success 和安全事件等分层指标。

D116 最终总结

1. 核心变化

π0.5 从短动作生成走向推理、规划和执行闭环。

2. 三层架构

Reasoning 负责分解，Skill 负责计划，Action 负责连续控制。

3. 长任务关键

持续观察、上下文管理、失败检测和动态重规划。

4. 工程接口

VLM 输出必须结构化，技能库必须有前置条件和后置效果。

5. 评估方式

除了最终成功率，还要看子任务、技能、恢复、安全和效率。
