条件注入：Action Expert 到底需要 VLM 提供什么

Action Expert 不是只需要一个“语言指令向量”。它需要从 VLM 条件中读到可执行控制相关的信息：目标、空间关系、任务意图、约束和当前状态线索。

VLM 条件应该包含

目标物体红杯子、抽屉把手、布料边缘、按钮
空间关系在左侧、靠近夹爪、位于容器内、被遮挡
任务意图抓取、打开、推入、折叠、对齐、插入
场景约束障碍物、桌面边缘、可接触区域、危险区域

为什么不是最终层

VLM 的最终层通常更贴近语言生成分布；中间层更可能保留视觉-语言融合表征。动作生成需要的是“任务条件”，不是一句流畅回答。

# 教学示意：提取中间层作为条件
mid_layer = 16  # 真实层数应通过配置和消融确定
layer_outputs = vlm(images, text, output_hidden_states=True)
condition = layer_outputs.hidden_states[mid_layer]
condition = condition_adapter(condition)
核心判断标准不是“第几层固定最好”，而是这层表征能否让 Action Expert 稳定读到与动作相关的语义和空间信息。

三种条件注入方式：FiLM、Concat、Cross-Attention

直觉

FiLM 把条件压缩成调制参数，用 gamma 和 beta 去缩放/平移动作特征。它像是在告诉 Action Expert：“当前任务下，哪些通道更重要”。

gamma = gamma_net(pooled_condition)
beta = beta_net(pooled_condition)
x = gamma * x + beta

优缺点

优点简单、快、显存低、容易实现
缺点通常需要池化条件，容易丢失空间和 token 结构
适合条件较简单、延迟要求很高、动作任务较固定

直觉

Concat 直接把动作特征和条件特征拼起来，然后交给后续 MLP/Transformer 自己学习融合。

cond = condition.mean(dim=1)
cond = cond[:, None, :].expand(-1, K, -1)
x = torch.cat([action_features, cond], dim=-1)
x = projection(x)

优缺点

优点直观，信息路径短，实现成本低
缺点条件和动作之间的细粒度对应关系需要后续网络自己学
适合小模型、快速 baseline、条件 token 不长的场景

直觉

Cross-Attention 让 action token 主动去查询 VLM condition token。每个动作时间步都可以根据自己当前状态，从图文条件里读取需要的信息。

attn_output = cross_attn(
    query=action_tokens,
    key=vlm_condition,
    value=vlm_condition,
)
action_tokens = action_tokens + attn_output

为什么常被选择

序列结构保留 VLM token 的空间和语言结构
细粒度对齐不同动作步可关注不同目标或约束
可解释性注意力权重可帮助调试条件是否被使用
代价比 FiLM/Concat 更重，需要控制 token 数和 hidden size
方式信息保留计算代价适合场景主要风险
FiLM低到中低低延迟、简单任务条件被压扁，空间关系丢失
Concat中中快速 baseline融合不够结构化
Cross-Attention高中到高复杂视觉语言条件、长动作 chunk显存和延迟更高
D114 的重点不是背“π0 一定用了某个固定层数和固定注入层数”，而是理解为什么复杂机器人任务需要细粒度条件读取。

Action Expert 内部：四类输入如何合成速度场

Action Expert 的输入至少包含：当前带噪动作、Flow Matching 时间步、VLM 条件、本体感受。输出是每个动作维度的速度场。

def forward(noisy_actions, t, vlm_condition, proprioception):
    action_emb = action_encoder(noisy_actions)       # [B,K,H]
    time_emb = time_encoder(t)[:, None, :]           # [B,1,H]
    prop_emb = proprio_encoder(proprioception)       # [B,K,H]

    x = action_emb + time_emb + prop_emb
    x = cross_attention(query=x, key=vlm_condition, value=vlm_condition)
    x = self_attention_over_action_chunk(x)
    velocity = output_head(x)                        # [B,K,D]
    return velocity

训练策略：保护 VLM，同时让 Action Expert 学会控制

D114 的训练核心是一个平衡问题：VLM 已经有视觉语言语义，Action Expert 是新学动作分布。训练太保守，Action Expert 不够适配；训练太激进，VLM 可能遗忘原有能力。

Stage 1冻结 VLM

只训练 Action Expert。目标是先让动作专家学会从稳定条件中预测速度场。

vlm_lr = 0
expert_lr = 1e-4
Stage 2轻微解冻

解冻 VLM 后几层或 adapter，让条件表征开始适配机器人数据。

vlm_lr = 1e-6
expert_lr = 1e-4
Stage 3联合微调

在更谨慎的学习率和数据混合下共同优化，追求更高上限。

vlm_lr = 1e-5
expert_lr = 1e-4

差异学习率

VLM 使用更小学习率，Action Expert 使用较大学习率，因为前者已有通用能力，后者需要从头学习动作分布。

数据混合

机器人数据提供动作监督，通用图文数据或语言辅助任务帮助 VLM 保持语义能力。

梯度裁剪

VLM 梯度通常应更严格，避免少量机器人数据造成表示漂移。

动作空间设计：VLA 落地最容易出错的地方

“输出 7 维动作”这句话远远不够。你必须说明每一维是什么、在哪个坐标系、是增量还是绝对值、如何归一化、如何安全裁剪。

典型 7 维 delta action

dx, dy, dz末端位置增量，单位通常是米
droll, dpitch, dyaw末端姿态增量，单位通常是弧度
gripper夹爪开合，可以是连续值、二值值或增量

必须额外说明

坐标系base frame / camera frame / end-effector frame
控制频率频率越高，每步 delta 应越小
限幅每步最大平移、最大旋转、夹爪范围
执行方式执行整个 chunk，还是只执行前几步再规划
增量动作更适合闭环控制：输出相对当前状态的小变化，训练分布更集中，也更容易跨场景泛化。
new_position = current_position + delta_xyz
new_rotation = current_rotation @ delta_rotation
new_gripper = clip(current_gripper + delta_gripper, 0, 1)
绝对动作表达直观，但强依赖标定和全局坐标。标定误差、相机外参误差、不同机器人坐标差异都会放大部署风险。
target_pose = {
    "position": action[0:3],
    "orientation": euler_to_matrix(action[3:6]),
    "gripper": action[6],
}
关节动作贴近底层控制器，适合固定机器人平台；但跨机器人泛化更难，语言目标到关节空间的映射也更复杂。
joint_targets = current_joints + delta_joints
joint_targets = clip(joint_targets, joint_lower, joint_upper)

Action Chunking：一次预测多步，但滚动执行

Action chunk 让模型一次生成一段动作，捕获短时序结构；receding horizon 让机器人只执行前几步后重新观察，避免长期误差累积。

动作归一化：连续动作模型能不能训稳的关键

连续动作并不意味着直接把米、弧度、夹爪状态混在一起训练。不同维度量纲不同，必须归一化到模型友好的范围，再在部署时反归一化。

归一化公式

# min/max 到 [-1, 1]
norm = 2 * (raw - low) / (high - low) - 1

# 反归一化
raw = (norm + 1) * (high - low) / 2 + low

0.10high
部署时最危险的错误之一是训练和推理使用了不同的动作统计或坐标系。模型看起来正常输出，但机器人动作幅度会完全错误。

动作空间扩展：从 7 维机械臂到灵巧手

灵巧手会把动作维度从 7 维扩展到 20、30 甚至更高。此时动作空间设计、分组归一化和延迟控制会变得更重要。

机械臂

通常关注末端位姿和夹爪，动作维度较低，适合讲清 delta pose、gripper 和控制频率。

灵巧手

每个手指关节都有动作维度，手部动作和腕部动作耦合强，需要单独归一化和约束。

高维风险

动作维度越高，数据需求越大，控制稳定性越难，action chunk 的长度和 ODE steps 都需要重新权衡。

arm_action = full_action[..., :7]
hand_action = full_action[..., 7:]

arm_norm = arm_normalizer.normalize(arm_action)
hand_norm = hand_normalizer.normalize(hand_action)
action_norm = torch.cat([arm_norm, hand_norm], dim=-1)

最小复现骨架：把 D114 三件事连起来

下面的骨架把中间层条件、Action Expert、Flow Matching 损失和差异学习率放在一起，方便你形成实现地图。

class PiZeroLike(nn.Module):
    def __init__(self, vlm, action_dim=7, hidden_dim=512, mid_layer=16):
        super().__init__()
        self.vlm = vlm
        self.mid_layer = mid_layer
        self.adapter = nn.Linear(vlm.hidden_size, hidden_dim)
        self.action_expert = ActionExpert(action_dim, hidden_dim)

    def forward(self, images, text, noisy_actions, t, proprio):
        vlm_out = self.vlm(images, text, output_hidden_states=True)
        condition = self.adapter(vlm_out.hidden_states[self.mid_layer])
        velocity = self.action_expert(noisy_actions, t, condition, proprio)
        return velocity

optimizer = AdamW([
    {"params": model.vlm.parameters(), "lr": vlm_lr},
    {"params": model.adapter.parameters(), "lr": 1e-4},
    {"params": model.action_expert.parameters(), "lr": 1e-4},
])

面试表达：D114 高频问题

π0-style 系统通常从 VLM 中间层取视觉语言融合表征，再通过 adapter 或 cross-attention 注入 Action Expert。Cross-attention 的优势是保留 token 结构，让每个动作步按需读取目标、空间关系和任务约束。
训练上通常先冻结 VLM，让 Action Expert 学会动作分布；之后可以轻微解冻 adapter 或 VLM 后几层，用小学习率适配机器人任务。这样是在 action performance 和 catastrophic forgetting 之间做折中。
动作空间必须说明维度、坐标系、delta/absolute、控制频率、gripper 编码、归一化和安全裁剪。连续动作不等于无约束动作，部署时反归一化和限幅非常关键。
如果让我设计一个 π0-style 系统：
1. 选预训练 VLM，提取中间层视觉语言条件；
2. 用 adapter/cross-attention 注入 Action Expert；
3. 定义 delta action space，并统一归一化；
4. 用 Flow Matching 训练速度场；
5. 先冻结 VLM，再小学习率解冻；
6. 推理时生成 action chunk，只执行前几步并重规划。

自测：确认你真的理解 D114

1. 为什么 Action Expert 不应该只接收一个池化后的语言向量？
因为动作生成需要目标物体、空间关系、场景约束等细粒度信息。单个池化向量容易丢失 token 结构和空间对应关系。
2. Cross-Attention 相比 FiLM 的核心优势是什么？
它允许动作 token 主动查询 VLM condition token，保留序列结构，并学习动作步和视觉语言条件之间的细粒度对应关系。
3. 为什么训练初期通常先冻结 VLM？
冻结 VLM 可以提供稳定条件，降低灾难性遗忘风险，让新初始化的 Action Expert 先学会动作速度场。
4. delta action 为什么常比 absolute action 更适合闭环机器人控制？
delta action 相对当前状态输出小变化，训练分布更集中，对全局坐标标定依赖更低，也更适合滚动重规划。
5. action chunk size 过大有什么风险？
chunk 太大虽然可能更平滑，但会增加开环预测跨度，环境变化和模型误差更容易累积，因此通常只执行前几步后重新规划。

D114 最终总结：必须带走的 6 个结论

1. 条件注入是双塔的桥

VLM 和 Action Expert 的关键不只是分开，而是如何把视觉语言条件有效传给动作专家。

2. Cross-Attention 的价值

它保留条件 token 结构，让动作序列按需读取目标、空间关系和任务约束。

3. 训练策略是稳定性核心

冻结、轻微解冻、差异学习率和数据混合，本质是在控制遗忘和动作适配之间的平衡。

4. 动作空间必须工程化

维度、坐标系、delta/absolute、gripper、归一化、限幅和控制频率都要明确。

5. Chunking 是平滑与闭环的折中

一次预测多步有助于时序一致性，但部署时通常只执行前几步再重规划。

6. 消融要讲趋势

不要死背教学数字，重点解释设计取舍和实验条件。
